# Into the Night

Географическая стратегия на глобусе: цель восточнее старта, прямой путь встречает смертельное Солнце — нужно облететь Землю на запад, выбирая последовательность реальных аэродромов для дозаправки. Управление строится вокруг карты и кнопки «Полёт» в карточке назначения.

## Новая концепция (принята 2026-10-23)

После проверки JFK → Heathrow исследуем первый этап Санкт-Петербург → Новосибирск/Академгородок и [предварительную кампанию](docs/CAMPAIGN.md): три части научного знания, Япония, полярная ночь в Антарктиде, Австралия за провизией, затем Шпицберген и бункер. Дата может меняться при сохранении северного полярного дня. Игрок выбирает следующий аэродром на глобусе и нажимает «Полёт». Заправка максимальная и автоматическая. Первый playable-этап пока без еды и ручного ожидания; они вернутся для сезонной кампании. Выбор на паузе не расходует UTC. Физический масштаб сохраняется.

Полная кампания и пригодный для неё первый сценарий ещё не подтверждены. [Рецензия и план](docs/CONCEPT_REVIEW.md), [дизайн](GAME_DESIGN.md), [контракт](SIMULATION.md), [проверка сценария](SCENARIOS.md).

## Исследовательские данные новой миссии

В #20 подготовлены reference-профиль Boeing 787-8 и 107 аэродромов с мировым покрытием, исходными ВПП и отдельными конечными складами. [Источники, допущения, ограничения и воспроизведение](docs/MISSION_DATA.md). Проверка: `npm run validate:mission-data`. Это ещё не подтверждение достижимости миссии и не обновление игрового интерфейса.

## Проверка достижимости (#21)

Проверяем полный западный обход с несколькими дозаправками. Августовский прямой Пулково → Толмачёво исключён из кандидатов. [Новое исследование](docs/WESTWARD_MISSION.md) подтвердило альтернативный SCEL → NZCH → YPPH → FACT на 23053 км с отдельными конечными складами по 32 т; прямой восточный рейс солнечно опасен. СПБ → Новосибирск ещё не подтверждён. Воспроизведение: `npm run research:westward`, сверка `npm run validate:westward`. Условия выбираются по реальному Солнцу; искусственного запрета лететь на восток нет.

[Прежний контроль Пулково → Толмачёво](docs/FIRST_CHAPTER_FEASIBILITY.md): вечерний рейс 20 августа проходит полёт и максимальную заправку при полярном дне на Шпицбергене, но даёт тупик для продолжения. Этот прямой вариант исключён из кандидатов; при прежнем старте за час до восхода на проверенных датах первого хода нет. Расширен каталог до 1183 аэропортов. После сборки: `npm run research:campaign`, сверка `npm run validate:campaign`; данные `npm run validate:campaign-data`.

Исторический [отчёт JFK → Heathrow](docs/MISSION_FEASIBILITY.md) и входы сохранены без изменения; команды `npm run research:mission -- --research` и `npm run validate:mission` продолжают воспроизводить его. Ни один отрицательный результат не является доказательством глобальной невозможности реальных маршрутов.

## Что сейчас можно запустить

Опубликованная игра и команды ниже пока запускают **предыдущий** трёхаэропортовый spike OSL/TOS/LYR с едой, ручными операциями и длительной стоянкой. Обновление документов не переключает игру на новую миссию. [Исторические результаты](docs/SPIKE_SCENARIO.md) подтверждают 30/90 суток именно прежней модели; они не доказывают JFK → Heathrow.

## Играть локально

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Выберите аэропорт, добавьте погрузку и перелёт, выполните план; после посадки обслужите самолёт и попробуйте длительное ожидание с паузой. Можно сохранить активное действие и экспортировать журнал для рецензии. Это экспериментальная версия на трёх аэропортах.

Сборка: `npm run build:web`, запуск сборки: `npm run serve:web`. [Управление, ручная проверка, сохранения и ограничения](docs/PLAYABLE_SPIKE.md).

## Запуск вычислительного ядра

Нужны Node.js 24 (проверено на 24.19.0), npm 11 и POSIX shell для процессных проверок CLI. Версия Node указана в `.nvmrc`, инструменты фиксированы lockfile. Установка зависимостей требует доступа к npm; дальнейшие расчёты и проверки работают офлайн.

```sh
npm ci
npm run check
npm run solar -- --utc 2026-11-20T03:00:00Z --lat 60.202778 --lon 11.083889
npm run validate:solar
npm run route -- --utc 2026-11-20T03:00:00Z --plan examples/oslo-tromso.json
npm run validate:route
```

Отдельные команды: `npm run typecheck`, `npm run build`, затем `npm test`. CLI выдаёт JSON с версиями, UTC, солнечным направлением, q, высотой в градусах и `safe`; ошибки — JSON в stderr и код выхода 1. Для чистого JSON можно вызвать `node dist/cli.js` с теми же аргументами. Время задаётся с явным `Z`, координаты — в градусах, долгота к востоку положительна.

Поддерживается 2020–2040 год включительно. Максимальная ошибка направления на 1346 независимых эталонах — 0.00839°; смещение геометрического восхода у полюса в контрольном случае достигает 7.6 минуты. Контракт, источники, лицензии и ограничения — в [отчёте о модели Солнца](docs/SOLAR_MODEL.md). Маршрут проверяется непрерывно консервативным адаптивным поиском: `safe`, `unsafe` с интервалом первого события <=1 с или `indeterminate`, если точности недостаточно. Прогноз и исполнение используют один валидатор. Формат плана, параметры поиска, команда `--mode execute` и ограничения — в [описании проверки маршрута](docs/ROUTE_SAFETY.md). Отдельная команда `route` проверяет солнечную геометрию; команда `simulation` также учитывает топливо, еду и действия.

Ресурсы и действия доступны без интерфейса:

```sh
npm run simulation -- --plan examples/resource-plan.json
npm run simulation -- --plan examples/resource-plan.json --mode execute
```

[Контракт симулятора ресурсов](RESOURCE_SIMULATION.md): загрузка, подготовка, перелёт, обслуживание, ручное ожидание, прогноз и подтверждение риска. После первой посадки в новый аэропорт продолжение плана требует раскрытия склада и нового планирования. Автоожидание, промежуточное состояние и сохранения реализованы.

Сезонная стоянка и автоматическая остановка:

```sh
npm run simulation -- --plan examples/polar-wait.json --mode standing
npm run simulation -- --plan examples/polar-wait.json --mode execute
npm run validate:waiting
```

[Контракт длительного ожидания](docs/LONG_WAITING.md): поиск первого Солнца на 370 суток, отдельный физический предел стоянки и конфигурируемые уведомления 72 часа еды / 12 часов до Солнца. Пример полюса — синтетическая проверка, не реальный аэропорт или подтверждённая стратегия.

Пауза и продолжение:

```sh
npm run simulation -- --plan examples/resource-plan.json --mode execute \
  --stop-at 2026-01-01T21:15:00Z --save /tmp/into-the-night.json
npm run simulation -- --restore /tmp/into-the-night.json --mode execute
npm run validate:sessions
```

[Формат сохранений и API stateAt](docs/SAVE_RESUME.md): просмотр даты без расхода времени, согласованная остановка и продолжение без повторных событий и передач ресурсов.

Контрольный сценарий и поиск стратегий:

```sh
npm run build
npm run spike -- --plan examples/spike/plans/direct-30.json
npm run spike -- --plan examples/spike/plans/seasonal-departure.json
npm run spike -- --research
npm run validate:spike
```

[Описание эксперимента](docs/SPIKE_SCENARIO.md) содержит источники и лицензию аэропортов, допущения, свидетельства 30/90 суток, сравнение запасов и границы поиска на 180 суток. Исследовательский отчёт печатает истинные склады и предназначен для проверки баланса.
