# Into the Night

Пошаговая веб-стратегия длительного выживания на глобусе. Солнце смертельно: планируйте перелёты между реальными аэропортами, загружайте топливо и еду и выбирайте, где переждать ночь — в том числе полярную.

## Идея игры

Цель — прожить максимально долго. Игрок управляет маршрутом и ресурсами самолёта с экипажем из 30 человек; пилотирования нет. Планирование не расходует игровое время, а перелёты, погрузка, обслуживание и ожидание выполняются в глобальном UTC.

- Безопасность зависит от положения Солнца на всей траектории и во время наземных действий.
- Склады аэропортов конечны и не восстанавливаются. До посадки известны приблизительные запасы, после — точные.
- Сезоны и полярная ночь позволяют планировать выживание на недели и месяцы.
- Прогноз и исполнение используют одну детерминированную модель симуляции.
- Достижения за 30, 90, 180 и 365 суток не завершают партию.

Первый сценарий начинается в Европе осенью, дальнейший маршрут свободный. Точный аэропорт, дата и запасы будут выбраны после проверки баланса.

## Статус

Реализованы модель Солнца и проверка полного маршрута: ортодромия, все наземные фазы, первый опасный момент и совпадающая с прогнозом остановка исполнения. Модель Солнца проверена по независимым эфемеридам. Ресурсы, длительное ожидание и интерфейс — следующие задачи.

Проходимость на 30/90/180/365 суток ещё не подтверждена. Прежняя цепочка Осло → Тромсё → Лонгйир — историческая регрессия, которую нужно пересчитать по новой модели питания.

## Запуск вычислительного ядра

Нужны Node.js 24 (проверено на 24.19.0), npm 11 и POSIX shell для процессных проверок CLI. Версия Node указана в `.nvmrc`, инструменты фиксированы lockfile. Установка зависимостей требует доступа к npm; дальнейшие расчёты и проверки работают офлайн.

```sh
npm ci
npm run check
npm run solar -- --utc 2026-11-20T03:00:00Z --lat 60.202778 --lon 11.083889
npm run validate:solar
npm run route -- --utc 2026-11-20T03:00:00Z --plan examples/oslo-tromso.json
npm run validate:route
```

Отдельные команды: `npm run typecheck`, `npm run build`, затем `npm test`. CLI выдаёт JSON с версиями, UTC, солнечным направлением, q, высотой в градусах и `safe`; ошибки — JSON в stderr и код выхода 1. Для чистого JSON можно вызвать `node dist/cli.js` с теми же аргументами. Время задаётся с явным `Z`, координаты — в градусах, долгота к востоку положительна.

Поддерживается 2020–2040 год включительно. Максимальная ошибка направления на 1346 независимых эталонах — 0.00839°; смещение геометрического восхода у полюса в контрольном случае достигает 7.6 минуты. Контракт, источники, лицензии и ограничения — в [отчёте о модели Солнца](docs/SOLAR_MODEL.md). Маршрут проверяется непрерывно консервативным адаптивным поиском: `safe`, `unsafe` с интервалом первого события <=1 с или `indeterminate`, если точности недостаточно. Прогноз и исполнение используют один валидатор. Формат плана, параметры поиска, команда `--mode execute` и ограничения — в [описании проверки маршрута](docs/ROUTE_SAFETY.md). Топливо и еда пока не учитываются.

## Порядок разработки

1. Подготовить минимальный проект, общий вычислительный модуль и CLI с командами запуска, сборки и проверок. Рекомендованный стек — TypeScript для браузера и CLI.
2. Реализовать и независимо проверить Солнце и геометрию маршрутов.
3. Добавить ресурсы, наземные операции, события и сохранения.
4. Подготовить каталог реальных аэропортов с источниками и лицензиями, выбрать фиксированный сценарий.
5. Проверить стратегии на 30, 90 и 180 суток; исследовать годовое выживание.
6. Подключить глобус, ручное планирование, сезонную перемотку и продолжение партии.

Выбор движка глобуса предстоит обосновать проверкой мобильного управления и геометрии. Симулятор должен оставаться независимым от интерфейса, FPS и сетевого доступа.

## Работа над проектом

Перед изменениями прочитайте документы выше. Каждая задача GitHub содержит цель, границы и проверяемые критерии. Для неё создаётся отдельная ветка с номером issue, например `1-init`. Сообщения коммитов начинаются с реального номера задачи и описывают выполненное действие: `#1 добавил документацию проекта`. В PR указываются результат, проверки и ограничения. PR вливает только владелец проекта.
