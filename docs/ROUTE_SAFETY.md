# Полный маршрут и солнечная безопасность

## Контракт и границы

Версия маршрута — `great-circle-solar-1`, конфигурация 1; Солнце — существующая `meeus-noaa-1`. `checkRouteSafety` и `executeSolarRoute` используют один валидатор. Это солнечная проверка: топлива, еды, скрытых складов и полного игрового состояния пока нет. Примеры не являются подтверждёнными стратегиями выживания или готовым каталогом аэропортов.

Вход: `startUtcMs` (UTC Unix milliseconds), `waypoints` (как минимум две точки с широтой/долготой в градусах), необязательный `initialServiceRequired` (по умолчанию false — стартовое обслуживание уже выполнено). Вход не мутируется; план содержит собственные неизменяемые снимки координат. Все моменты плана должны находиться в диапазоне модели Солнца 2020–2040 включительно. Время в числовых UTC-полях сохраняет дробные миллисекунды; ISO-поля CLI служат для чтения и округлены вниз до миллисекунды.

Каждый участок: подготовка 15 минут → взлёт 15 минут в точке отправления → движение по дуге со скоростью 850 км/ч → посадка 15 минут в точке назначения → обслуживание 15 минут. Проверяются все фазы, включая финальное обслуживание. Если необходимо, перед первым участком добавляется начальное обслуживание. Время наземных операций не включается в расстояние. Увеличение длины маршрута не отменяет проверку предыдущих участков.

Позицию и нормаль активной фазы дают `routePhasePosition` / `routePhaseNormal`. Земля сферическая, R=6371.0088 км. Угол вычисляется устойчивым эквивалентом acos(dot): atan2(|n0×n1|, n0·n1). Интерполяция идёт в плоскости кратчайшей дуги по ортонормальному базису, без линейной интерполяции долготы. Переход ±180° и полярная дуга не являются особыми маршрутными запретами. В самом полюсе отображаемая долгота условно равна нулю.

Совпадающие точки (угол <=1e-10 радиан, около 0.6 мм по поверхности) отклоняются. Почти антиподальные точки (отклонение от π <=1e-6 радиан, около 6.4 м) отклоняются до выбора устойчивой неоднозначной дуги. Это численная обработка совпадения/антиподов, а не ограничение ночных маршрутов или полярной стоянки.

## Как проверяется интервал между отсчётами

Проверяем q(t)=n(t)·s(t), где t в секундах и безопасно строго q<0. Для каждой гладкой фазы задана консервативная граница |q''|<=M. Ошибка линейной интерполяции функции с ограниченной второй производной не превосходит M·Δt²/8. Поэтому весь интервал можно отбросить как безопасный только при

```
max(q(t0), q(t1)) + M·Δt²/8 + E < 0.
```

Если неравенство не выполнено, интервал делится пополам и обходится строго по времени. Это не проверка только концов и не предположение монотонности: светлая середина при тёмных концах и локальный максимум у горизонта сохраняются для уточнения.

Для дуги постоянной угловой скорости w имеем |n'|=w, |n''|=w². Для земли w=0. Для модели Солнца используются |s'|<=8e-5 рад/с и |s''|<=8e-9 с⁻². Тогда

```
M = w² + 2w·8e-5 + 8e-9.
```

w вычисляется из фактического угла и длительности фазы, учитывая округление UTC при построении плана.

Обоснование солнечных границ для 2020–2040: вектор до земного вращения можно записать как (cos L, cos ε·sin L, sin ε·sin L), затем вращать на -GAST. Из коэффициентов `solar.ts` для t∈[0.2,0.41] юлианского столетия: |GAST'|<7.3e-5 рад/с, |L'|<2.2e-7 рад/с, |ε'|<1e-12 рад/с; сумма абсолютных вторых производных углов меньше 1e-12 с⁻². Скорость композиции вращений ограничена суммой скоростей, её вторая производная — квадратом этой суммы плюс суммой угловых вторых производных. Получаем запас относительно 8e-5 и 8e-9. Отсутствие сингулярности в этой записи не зависит от ветки atan2 прямого восхождения.

E=1e-8 — численный запас для сертификата отрицательности, а не новая граница поражения. В double-арифметике даты диапазона юлианская дата имеет шаг около 40 мкс; его половина даёт ошибку земного угла около 1.5e-9 радиан. Запас 5e-9 на вычисление q покрывает это округление и тригонометрические/векторные операции; интерполяция использует два таких запаса (в концах и внутри). Это численная оценка для стандартной double-арифметики JavaScript, а не формальное доказательство реализации Math.sin для любого движка. Изменение модели Солнца требует повторной проверки границ; несовпадение её версии с конфигурацией маршрута блокирует проверку.

## Результаты и первый момент опасности

- `safe`: все интервалы и все фазы сертифицированы до конца плана; события нет.
- `unsafe`: найден фактический отсчёт q>=0. `event` содержит UTC этого отсчёта, положение, фазу, индекс участка, q и интервал первого возможного опасного момента `bracketUtcMs`. Весь предшествующий префикс проверен; ширина интервала не превышает запрошенной точности (по умолчанию 0.5 с, максимум 1 с).
- `indeterminate`: первым остаётся неразрешённый интервал либо исчерпан бюджет. Причина — `near_horizon` / `evaluation_budget`, указаны `safeUntilUtcMs` и `unresolvedIntervalUtcMs`; поражение и безопасность остатка не утверждаются.

При положительном q на старте событие возникает сразу с нулевой шириной интервала. Фазы проверяются в порядке времени, включая их общие границы. `safeUntilUtcMs` обозначает конец гарантированно проверенного префикса: при опасности сама граница события в безопасный префикс не входит.

Неопределённые короткие интервалы не пропускаются: более поздний положительный отсчёт может подтвердить поражение только если вся область первого возможного события помещается в заданный временной допуск. Иначе возвращается `indeterminate`, даже если дальше известно дневное освещение. Это предотвращает ошибочное объявление более позднего пересечения первым.

Касание q=0 без смены знака опасно при подтверждённом нулевом отсчёте. Если точное касание находится между отсчётами и численно неотличимо от отрицательного минимума запаса, возвращается `indeterminate`; небольшое отрицательное q не округляется в поражение. Узкий светлый участок, который пока не удалось разрешить, также не становится безопасным. Поиск экстремума с произвольным epsilon не используется для объявления смерти.

По умолчанию начальный интервал <=900 с, допуск события 0.5 с, бюджет на весь план 100000 вычислений. Минимальный лист — допуск/32. Эти параметры определяют работу поиска, а не механику Солнца. Шаг, слишком малый для изменения представимого UTC timestamp, отклоняется вместо бесконечного цикла. Изменение параметров может уточнить результат, но не гарантирует разрешение математически пограничного случая. Если точности недостаточно, выполнение возвращает `needs_refinement` и останавливается на конце проверенного префикса.

`executeSolarRoute` возвращает `completed`, `solar_death` либо `needs_refinement`, UTC остановки и положение. При смерти остановка совпадает с подтверждённым опасным отсчётом прогноза, от первого события он отделён не более чем указанной шириной интервала. Ресурсные дельты и полноценная машина событий будут добавлены в #5.

Точность <=1 с относится к событию выбранной игровой модели. Физическое смещение полярного восхода относительно независимой эфемериды из #3 (до 7.6 минуты в контрольном случае) сохраняется; поиск маршрута его не устраняет.

## Воспроизведение

```sh
npm ci
npm run check
npm run route -- --utc 2026-11-20T03:00:00Z --plan examples/oslo-tromso.json
npm run route -- --utc 2026-03-20T00:00:00Z --plan examples/dark-endpoints.json
npm run route -- --utc 2026-03-20T00:00:00Z --plan examples/dark-endpoints.json --mode execute
npm run validate:route
```

Для чистого JSON вызывайте `node scripts/route-cli.mjs` или `node scripts/validate-route.mjs`. Ошибки входа/файла дают JSON в stderr и код выхода 1; корректный расчёт, включая unsafe/indeterminate, — JSON в stdout и код 0. CLI не обращается к сети. `--event-tolerance`, `--max-interval`, `--max-evaluations` позволяют повторить уточнение. JSON-план содержит только waypoints и необязательный initialServiceRequired.

## Проверки и отчёт

25 тестов включают существующую независимую проверку Солнца, аналитическую дугу на экваторе, ±180°, полюс, совпадение/антиподы, светлую середину, нулевое касание, неразрешимое касание между отсчётами, узкий светлый пик, исчерпание бюджета, порядок первого события и все наземные фазы. Процессные проверки CLI выполнены в четырёх часовых поясах, включая остановку исполнения и ошибки файла.

[route-validation.json](route-validation.json) фиксирует четыре геометрических примера и 16 сочетаний начального шага (3600/900/120/30 с) и допуска (1/0.5/0.1/0.01 с). Контрольный случай с тёмными концами на экваторе обнаруживает поражение в 2026-03-20T07:45:32.876Z, при настройках по умолчанию ширина интервала около 0.013733 с. Прогноз и исполнение совпадают. Осло–Тромсё, пересечение 180° и зимняя полярная дуга безопасны по Солнцу в указанных датах.

Дополнительный регрессионный эталон в отчёте сканирует эти конкретные случаи каждую секунду и уточняет найденное пересечение бисекцией. Он подтверждает сходимость, но не служит сертификатом для произвольного маршрута: узкие опасные участки в общем случае защищены оценкой M, а не плотностью этой сетки. Координаты контрольных примеров не заменяют проверку аэропортов и ВПП.
