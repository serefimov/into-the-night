# Данные мировой миссии (#20)

## Статус

Задача #20 реализована в слитом [PR #27](https://github.com/serefimov/into-the-night/pull/27): профиль реального самолёта, мировой каталог, отдельные конечные склады, источники и воспроизводимые проверки. Затем каталог расширен в #21, общий игровой цикл подключён в #22–#23, правило дозаправки обновлено в #39. Основа концепции — [решение #10](CONCEPT_REVIEW.md).

Браузер и CLI используют Boeing 787-8 и каталог из **1183 аэропортов**. Текущий аэропортовый этап — [Санкт-Петербург → Новосибирск](ACADEMIC_WESTWARD.md), старт 1 августа 2026 20:00 UTC, 30000 кг на борту и конечные игровые склады по 64000 кг. Его достижимость проверяется отдельным отчётом #21, а не выводится из одного наличия данных.

Выбран **Boeing 787-8 (B788)**, reference-v1. Профиль отделяет проверенные факты от явных приближений. Содержательные инварианты проверяются, но кривая расхода по массе/высоте не сертифицирована и не выдаётся за AFM. Вероятность пройти JFK → Heathrow не использовалась при выборе чисел.

## Источники самолёта

- [Boeing D6-58333, Rev Q, October 2025](https://www.boeing.com/content/dam/boeing/v2/airports/acaps/787_ACAP_Rev_Q.pdf), разделы 2.1.1 и 3.2.1: бак 126206 л, предельные взлётная/посадочная/безтопливная массы 227930/172365/161025 кг, reference cruise Mach 0.85. Документ защищён авторским правом; PDF/графики не перепубликуются, сохранены факты и ссылка.
- [EUROCONTROL B788](https://contentzone.eurocontrol.int/aircraftperformance/details.aspx?ICAO=B788&ICAOFilter=B788): reference TAS 470 узлов, дальность 8000 морских миль и опорные дистанции взлёта/посадки 2820/1520 м. Это ориентиры для проверки масштаба, не гарантированные характеристики при любой нагрузке и условиях.

В data/mission/aircraft.json источники привязаны к полям. Проверено 2026-10-23. Факты и ссылки не означают открытой лицензии на документацию Boeing/полную базу EUROCONTROL. Собственный код GPL-3.0-only, документация производителей в репозиторий не включена.

## Рабочая аппроксимация и её ограничения

| Величина | Reference-v1 |
| --- | --- |
| TAS, без ветра | 470 × 1.852 = 870.44 км/ч |
| Плотность топлива | 0.8 кг/л, фиксированное допущение |
| Полный используемый бак | 126206 × 0.8 = 100964.8 кг |
| Безтопливная масса | 126000 кг, условная лёгкая конфигурация |
| Крейсерский расход | 6.5 кг/км, постоянное приближение |
| Фазы отправления/прибытия | 900/900 с, 1800/200 кг на фазу |
| Наземное обслуживание | 600 с; двигатель выключен, расход 0 в этой модели |
| Подключение заправки / поток | 300 с / 1000 л/мин (800 кг/мин) |
| Планировочный резерв | 5000 кг, reference assumption, не нормативный расчёт резерва |

Безтопливная масса — сумма пустого самолёта и нагрузки в рассматриваемой конфигурации, а не заявленная Boeing масса пустого борта или полная пассажирская загрузка. Бак ограничен объёмом, масса получается из выбранной плотности. Не смешивать её с табличной массой Boeing при другой плотности.

Постоянный расход, времена фаз, сервис, резерв и унифицированный поток — **допущения**, не извлечённые значения AFM или сведения о конкретном аэропорте. Они дают согласованный межконтинентальный масштаб: полный бак с фиксированными фазами и reference-резервом — около 14456 км; сравнение с опубликованной дальностью проверяет правдоподобие, но не валидирует расход на всех нагрузках. Численные свидетели #21 относятся к этой reference-модели; они не доказывают достижимость для любых реальных нагрузок, расходов и наземных расписаний. Изменение допущений требует отдельной проверки и явной версии.

Физика здесь включает фактические расстояния, реальные скорости и массы; не включает ветер, детальный набор высоты, зависимость расхода от массы, погоду/рельеф, ограничения ETOPS и сертификационный расчёт взлёта. Автоматические наземные операции занимают время. Геометрическая модель Солнца и высота самолёта остаются в рамках SIMULATION.md; геометрию не дублируем.

**Посадочная масса проверяется отдельно от топлива.** С полным баком короткий рейс менее примерно 8092 км превышает максимальную посадочную массу: такой ход остаётся недопустимым. Однако полный бак больше не навязывается после посадки. По принятому в #39 правилу общий модуль рассчитывает дозаправку перед выбранным рейсом: расход полёта и обязательного обслуживания плюс существующий резерв 5000 кг, за вычетом топлива на борту. Лишнее уже имеющееся топливо не сливается. Ограничения ёмкости, складов, взлётной и посадочной массы сохраняются. [Формула и контрольные маршруты](DEPARTURE_FUEL.md).

[src/core/aircraft.ts](../src/core/aircraft.ts) содержит общие расчёты массы, расхода и передачи топлива; вызов заправки без заданного целевого количества сохраняет прежнюю максимальную загрузку для исторических отчётов. Текущие прогноз и исполнение используют [mission-flight.ts](../src/core/mission-flight.ts) и [MissionSession](../src/core/mission.ts), общие для CLI, браузера и worker. Солнечная безопасность всей последовательности, включая исходную заправку, проверяется существующим общим ядром.

## Аэродромы и лицензия

Текущий каталог data/campaign охватывает 1183 аэропорта: все large_airport в закреплённом snapshot и явно выбранные medium_airport, включая ULLI, UNNT и ENSB. Правило выбора записано в [data/campaign/selection.json](../data/campaign/selection.json). Есть шесть регионов AF/AS/EU/NA/OC/SA: Северная/Южная Америка, Тихий океан, Азия, Африка и Европа. Это каталог с мировым покрытием, а не все существующие аэродромы; отсутствие записи не доказывает отсутствие реального маршрута. Файлы регионов разделены на части, последовательность посадок не предписана.

Исходная выборка из 107 аэропортов в data/mission/selection.json сохранена для воспроизведения прежнего JFK-исследования; её не нужно заменять новым каталогом ради обновления игры.

Источник — [OurAirports](https://ourairports.com/data/), [словарь](https://ourairports.com/help/data-dictionary.html), Public Domain, без гарантии точности. Закреплён snapshot [11e4de2834aff6ab54c1f8fc89b8679ea3d08418](https://github.com/davidmegginson/ourairports-data/tree/11e4de2834aff6ab54c1f8fc89b8679ea3d08418), получен 2026-10-23. Оба catalog.json содержат commit, дату и SHA-256 обоих исходных CSV. Поле sourceId записи ссылается на эти общие метаданные источника/даты/лицензии; не требуется копировать их в каждую строку аэропорта. Полные CSV не требуются в поставке; региональные файлы содержат только выбранные записи.

Сохранены внутренний устойчивый числовой OurAirports ID, строковый ident, IATA/ICAO, название, страна/регион, координаты, высота и до трёх самых длинных открытых ВПП с sourceRowId, длиной, шириной и покрытием. Строковый ident может отличаться от актуального ICAO: Lima имеет ident SPIM, отдельно сохранён код из данных. Координаты/названия/ВПП взяты из snapshot, а не нарисованы вручную.

### Пригодность

Предварительный фильтр: открытая полоса с покрытием ASP/CON/BIT/PEM, длиной минимум 3000 м и шириной минимум 45 м. Это консервативный геометрический отбор для исследования, не универсальное правило B788 или замена AFM. В текущем каталоге 655 записей имеют status screened-candidate, 528 — unverified; у всех operationalApproval=false. В сохранённой выборке из 107 аэропортов соотношение 102/5.

В прежней выборке PABE, PHTO, SBEG, TNCM, WADD не проходят фильтр: статус unverified. В текущем каталоге, например, ENSB также unverified: полоса короче принятого порога. Пригодность не выдумывается и по умолчанию не используется как подтверждённая. Включение таких площадок требует обоснования и новой версии данных. JFK, Heathrow и контрольные PHNL/RJTT/FACT/SCEL имеют исходные записи подходящих по этому фильтру ВПП.

Несущая способность покрытия, препятствия, температура/высота, реальные службы заправки и эксплуатационные разрешения не проверены. Любая проверка #21 на screened-candidate остаётся исследованием при этих допущениях, не разрешением реального полёта.

## Конечное топливо

География и игровые склады разделены. Ни один файл запасов не заявляет реальные остатки топлива в аэропорту. Запасы публичны до вылета, конечны и не восстанавливаются при повторном посещении.

Исторические data/mission/fuel.json и data/campaign/fuel.json имеют stockVersion 1, единицы кг, public=true и regeneration=false. Для первого seed — jfk-heathrow-research-v1, для второго — academic-campaign-research-v1. Запасы 100000–400000 кг воспроизводятся SHA-256 от seed и числового OurAirports ID независимо от порядка обхода. Эти файлы продолжают обслуживать свои старые исследования.

**Текущая игра не берёт стартовые склады из этих исторических fuel.json.** [Загрузчик сценария](../scripts/mission-cycle-data.mjs) создаёт их по конфигурации academic-westward-v2: scenarioVersion 2, stockVersion departure-stocks-v2, seed academic-westward-v2, по 64000 кг каждому аэропорту, без исключений. Это явные параметры выбранного этапа #21. Конфигурация южного контроля westward-control-v2.json остаётся отдельной: по 64000 кг, SCEL 100000 кг.

Дозаправка уменьшает только фактически использованный склад отправления. Просмотр карточек его не расходует; отказ не меняет UTC/топливо/склады. После посадки запас назначения остаётся нетронутым до выбора следующего рейса. Определение и версии сохраняются вместе с партией; новая конфигурация не интерпретирует старое сохранение молча.

## Воспроизведение и проверки

Node 24 и Python 3, только стандартная библиотека импортера. Для проверки сохранённых данных сеть не нужна:

```sh
npm run validate:mission-data
npm run validate:campaign-data
node --test --test-isolation=none test/mission-data.test.mjs
python3 scripts/test-mission-import.py
npm run check
```

Для повторного импорта pinned CSV (этим командам импортера нужна сеть, если не передан --source-dir):

```sh
python3 scripts/import-mission-airports.py
node scripts/mission-data.mjs --write
git diff --exit-code -- data/mission/airports data/mission/catalog.json data/mission/fuel.json
# Текущий расширенный каталог с тем же закреплённым источником:
python3 scripts/import-mission-airports.py --selection data/campaign/selection.json --output .build/campaign-import/airports.json
node scripts/campaign-data.mjs --write
git diff --exit-code -- data/campaign
```

Можно передать --source-dir /path/to/csv для локальных CSV; importer запишет их контрольные суммы. Результат сначала создаётся в .build/mission-import, затем разделяется по регионам. Изменение источника/выборки или правил отбора — явное изменение версии данных, не незаметное обновление во время запуска игры.

Workflows [Import pinned mission data](../.github/workflows/mission-data.yml) и [Import pinned campaign data](../.github/workflows/campaign-data.yml) выполняют соответствующие импорты и сверяют файлы с репозиторием; предусмотрены ручной запуск и артефакты импорта. Флаг --log-archive выводит сжатый JSON уже полученных открытых данных для переноса через логи. Сам по себе он не отключает скачивание CSV; для локального импорта без сети нужен --source-dir.

Проверяются единицы и массы, дальний рейс, невозможность полной заправки с короткой посадкой, баланс/нулевая заправка, испорченные данные/координаты/дубли, детерминированность складов, отбрасывание закрытых/неполных ВПП и преобразование футов в метры. Старые солнечные/маршрутные проверки продолжают работать. Текущий сценарий отдельно сверяется командой npm run validate:academic, южный контроль — npm run validate:departure.

## Границы завершённой #20

Все критерии данных #20 покрыты профилем, каталогами, отдельными складами, источниками, импортом и проверками. Само наличие этих данных не доказывает миссию; полный западный аэропортовый этап проверен отдельно и принят в слитом PR #46 по #21.

Полная эксплуатационная пригодность Шпицбергена и антарктических полос/самолёта — #32. Получение знаний, поездка в Академгородок, лабораторные длительности и полная цепочка Японии — #31. Они не являются незавершённой частью каталога #20 и не обещаются геометрическим отбором.
