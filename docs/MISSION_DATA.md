# Данные мировой миссии (#20)

## Статус

Данные для исследования #21, а не готовая миссия. Новый интерфейс, игровая дата и начальная загрузка ещё не выбраны. Текущий spike не переключён на новый профиль. Основа концепции — [решение #10](CONCEPT_REVIEW.md).

Выбран **Boeing 787-8 (B788)**, reference-v1. Профиль отделяет проверенные факты от явных приближений. Содержательные инварианты проверяются, но кривая расхода по массе/высоте не сертифицирована и не выдаётся за AFM. Вероятность пройти JFK → Heathrow не использовалась при выборе чисел.

## Источники самолёта

- [Boeing D6-58333, Rev Q, October 2025](https://www.boeing.com/content/dam/boeing/v2/airports/acaps/787_ACAP_Rev_Q.pdf), разделы 2.1.1 и 3.2.1: бак 126206 л, предельные взлётная/посадочная/безтопливная массы 227930/172365/161025 кг, reference cruise Mach 0.85. Документ защищён авторским правом; PDF/графики не перепубликуются, сохранены факты и ссылка.
- [EUROCONTROL B788](https://contentzone.eurocontrol.int/aircraftperformance/details.aspx?ICAO=B788&ICAOFilter=B788): reference TAS 470 узлов, дальность 8000 морских миль и опорные дистанции взлёта/посадки 2820/1520 м. Это ориентиры для проверки масштаба, не гарантированные характеристики при любой нагрузке и условиях.

В data/mission/aircraft.json источники привязаны к полям. Проверено 2026-10-23. Факты и ссылки не означают открытой лицензии на документацию Boeing/полную базу EUROCONTROL. Собственный код GPL-3.0-only, документация производителей в репозиторий не включена.

## Рабочая аппроксимация и её ограничения

| Величина | Reference-v1 |
| --- | --- |
| TAS, без ветра | 470 × 1.852 = 870.44 км/ч |
| Плотность топлива | 0.8 кг/л, фиксированное допущение |
| Полный используемый бак | 126206 × 0.8 = 100964.8 кг |
| Безтопливная масса | 126000 кг, условная лёгкая конфигурация |
| Крейсерский расход | 6.5 кг/км, постоянное приближение |
| Фазы отправления/прибытия | 900/900 с, 1800/200 кг на фазу |
| Наземное обслуживание | 600 с; двигатель выключен, расход 0 в этой модели |
| Подключение заправки / поток | 300 с / 1000 л/мин (800 кг/мин) |
| Планировочный резерв | 5000 кг, reference assumption, не нормативный расчёт резерва |

Безтопливная масса — сумма пустого самолёта и нагрузки в рассматриваемой конфигурации, а не заявленная Boeing масса пустого борта или полная пассажирская загрузка. Бак ограничен объёмом, масса получается из выбранной плотности. Не смешивать её с табличной массой Boeing при другой плотности.

Постоянный расход, времена фаз, сервис, резерв и унифицированный поток — **допущения**, не извлечённые значения AFM или сведения о конкретном аэропорте. Они дают согласованный межконтинентальный масштаб: полный бак с фиксированными фазами и reference-резервом — около 14456 км; сравнение с опубликованной дальностью проверяет правдоподобие, но не валидирует расход на всех нагрузках. В #21 нужна чувствительность к допущениям; достижимость, зависящая от неточного расхода/времени, не называется доказанной для реального борта.

Физика здесь включает фактические расстояния, реальные скорости и массы; не включает ветер, детальный набор высоты, зависимость расхода от массы, погоду/рельеф, ограничения ETOPS и сертификационный расчёт взлёта. Автоматические наземные операции занимают время. Геометрическая модель Солнца и высота самолёта остаются в рамках SIMULATION.md; геометрию не дублируем.

**Посадочная масса проверяется отдельно от топлива.** С этим полным баком короткий рейс менее примерно 8092 км превышает максимальную посадочную массу: такой ход не разрешается молча. Сброс топлива и автоматическое урезание заправки не добавлены. Значение reference-профиля — выявить подобное ограничение до UI, а не гарантировать проход миссии. Начальное топливо JFK определит #21. Если обязательная максимальная заправка мешает пройти миссию, это результат для обсуждения с владельцем, не повод убрать ограничение скрытно.

src/core/aircraft.ts содержит чистые общие расчёты массы/ресурсов, полёта и максимальной заправки. Они ещё не встроены в старый симулятор. Проверка солнечной безопасности остаётся существующему общему ядру; этот модуль её не заменяет.

## Аэродромы и лицензия

107 выбранных аэродромов, шесть регионов AF/AS/EU/NA/OC/SA: Америка, Тихий океан, Азия, Африка, Европа. Это исследовательская выборка, не полный мировой каталог; отсутствие аэропорта не доказывает отсутствие реального маршрута. Выбор перечислен в data/mission/selection.json, без предписанной последовательности посадок.

Источник — [OurAirports](https://ourairports.com/data/), [словарь](https://ourairports.com/help/data-dictionary.html), Public Domain, без гарантии точности. Закреплён snapshot [11e4de2834aff6ab54c1f8fc89b8679ea3d08418](https://github.com/davidmegginson/ourairports-data/tree/11e4de2834aff6ab54c1f8fc89b8679ea3d08418), получен 2026-10-23. data/mission/catalog.json содержит commit, дату и SHA-256 обоих исходных CSV. Полные CSV не требуются в поставке; региональные файлы содержат только выбранные записи.

Сохранены внутренний устойчивый числовой OurAirports ID, строковый ident, IATA/ICAO, название, страна/регион, координаты, высота и до трёх самых длинных открытых ВПП с sourceRowId, длиной, шириной и покрытием. Строковый ident может отличаться от актуального ICAO: Lima имеет ident SPIM, отдельно сохранён код из данных. Координаты/названия/ВПП взяты из snapshot, а не нарисованы вручную.

### Пригодность

Предварительный фильтр: открытая полоса с покрытием ASP/CON/BIT/PEM, длиной минимум 3000 м и шириной минимум 45 м. Это консервативный геометрический отбор для исследования, не универсальное правило B788 или замена AFM. 102 записи имеют status screened-candidate; у всех operationalApproval=false.

PABE, PHTO, SBEG, TNCM, WADD не проходят фильтр: статус unverified. Пригодность не выдумывается и по умолчанию не используется как подтверждённая. Включение таких площадок требует обоснования и новой версии данных. JFK, Heathrow и контрольные PHNL/RJTT/FACT/SCEL имеют исходные записи подходящих по этому фильтру ВПП.

Несущая способность покрытия, препятствия, температура/высота, реальные службы заправки и эксплуатационные разрешения не проверены. Любая проверка #21 на screened-candidate остаётся исследованием при этих допущениях, не разрешением реального полёта.

## Конечное топливо

data/mission/fuel.json отдельно от географии: экспериментальные игровые склады в кг, seed jfk-heathrow-research-v1, без регенерации, количество публично. Запас 100000–400000 кг определяется SHA-256 от seed и числового OurAirports ID, независимо от порядка обхода. Это не сведения о реальных запасах аэропортов и не числа, подобранные под маршрут. Окончательные начальные условия/seed миссии закрепляет #21 с новой версией при изменениях.

## Воспроизведение и проверки

Node 24 и Python 3, только стандартная библиотека импортера. Для проверки сохранённых данных сеть не нужна:

```sh
npm run validate:mission-data
node --test --test-isolation=none test/mission-data.test.mjs
python3 scripts/test-mission-import.py
npm run check
```

Для повторного импорта pinned CSV (сеть нужна только этой команде):

```sh
python3 scripts/import-mission-airports.py
node scripts/mission-data.mjs --write
git diff --exit-code -- data/mission/airports data/mission/catalog.json data/mission/fuel.json
```

Можно передать --source-dir /path/to/csv для локальных CSV; importer запишет их контрольные суммы. Результат сначала создаётся в .build/mission-import, затем разделяется по регионам. Изменение источника/выборки или правил отбора — явное изменение версии данных, не незаметное обновление во время запуска игры.

Workflow «Import pinned mission data» выполняет те же шаги и сверяет файлы с репозиторием; есть ручной запуск, артефакт импорта. Для восстановления в окружении без исходящих сокетов поддерживается --log-archive: только открытые данные каталога в сжатом виде, без секретов или игрового состояния.

Проверяются единицы и массы, дальний рейс, невозможность полной заправки с короткой посадкой, баланс/нулевая заправка, испорченные данные/координаты/дубли, детерминированность складов, отбрасывание закрытых/неполных ВПП и преобразование футов в метры. Старые солнечные/маршрутные проверки продолжают работать. #21 остаётся отдельной обязательной точкой решения.
