# Первый playable spike

Минимальная браузерная версия для рецензии. Использует сценарий #8: три реальных аэропорта OSL/TOS/LYR, старт 2026-11-20 00:00 UTC. Можно выбрать любой аэропорт, выполнить отдельные операции или пакет действий. Заранее заданного маршрута нет. Правила и большие зимние склады остаются экспериментальными; 30/90 суток проверены, 180 суток и следующий сезон не подтверждены.

## Запуск

Node.js 24, npm 11:

```sh
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. Сервер работает локально; внешних сервисов, картографических SDK и загрузки тайлов нет. Для проверки с телефона в своей сети:

```sh
npm run dev -- --host 0.0.0.0 --port 5173
```

На телефоне откройте `http://<LAN-IP компьютера>:5173`. Это локальный сервер разработки, не публичный релиз.

Сборка браузерной версии и её запуск:

```sh
npm run build:web
npm run serve:web
```

Результат — `.build/spike`: HTML/CSS, ES-модули общего ядра и контрольные JSON. Отдельных npm-зависимостей для интерфейса нет. Статический сервер отдаёт только файлы игры и описание сценария. Сборка ядра/CLI продолжает работать прежними командами.

## Ручная проверка и рецензия

1. Начните новую партию. Посмотрите карточки TOS и LYR: склады приблизительные; в OSL остатки уже открыты. Выбор назначения не меняет UTC.
2. Введите погрузку 600 кг топлива / 12 часов еды экипажа, добавьте в план. Выберите LYR, добавьте перелёт с подготовкой. Карточка назначения оценивает перелёт из текущего состояния; прогноз пакета ниже также учитывает добавленную погрузку.
3. Посмотрите будущий UTC `2026-11-20T04:00:00Z`, затем вернитесь к текущему UTC. Прогноз явно помечен; посадка в предпросмотре не раскрывает склад. Просмотр останавливается в конце рассчитанного пакета или на первом событии.
4. Выполните пакет. Во время полёта нажмите «Пауза», сохраните, продолжите сохранение. Перемотка восстановится на паузе в том же месте. «До конца действия» доведёт до посадки либо первого поражения.
5. Выполните обслуживание, добавьте ручное ожидание на 30 суток. При перемотке календарь, еда, положение и освещение соответствуют одному показанному UTC. По умолчанию весь пакет занимает 12 секунд; можно выбрать сутки/месяц/час за секунду.
6. Поставьте ожидание на паузу примерно в середине либо выберите точку ползунком. Сохраните и восстановите; UTC и склад должны совпасть. «Продолжить» завершает ту же операцию; «Остановить на земле» завершает её в текущем месте и возвращает планирование. Ресурсы сохраняют фактический расход. В полёте доступна пауза, отменять полёт нельзя.
7. Попробуйте автоожидание. Оно останавливается на первом пищевом/солнечном пороге, без автопогрузки или вылета. Максимальная стоянка отдельно показывает ограничение; её конечная граница может быть моментом гибели, безопасный интервал её не включает. Поиск Солнца — на 370 суток с отдельным статусом неопределённости/ограниченного диапазона модели.
8. Из новой партии попробуйте ожидание суток в OSL: появляется явное подтверждение Солнца с UTC гибели. Отмена не расходует время; подтверждение приводит к первому поражению и итоговому экрану. Аналогично работает голод. Погрузка сверх склада/вместимости и нехватка топлива блокируются.
9. Скачайте сохранение и журнал, приложите их к рецензии: что было понятно, какое решение оказалось интересным, где ожидание или предупреждения раздражали. Концепцию пока не развиваем до обратной связи.

## Карта и управление

Выбрана простая Canvas-карта в равноугольной проекции: достаточно для трёх контрольных аэропортов, не требует движка/тайлов и работает кнопками на узком экране. Схематические контуры материков нарисованы для ориентации, не являются географическим каталогом. Сетка освещения с шагом 3° использует `solarDirection` и нормали общего ядра на показанный UTC; точечная солнечная безопасность аэропортов использует `solarExposure`. Растер терминатора — визуальное приближение, безопасность по нему не оценивается.

Маршрут выбирается кнопками OSL/TOS/LYR, списком назначения или ближайшей меткой. Линия строится из ортодромии ядра и разбивается на шве ±180°. Проверены северный полярный проход и маршрут через даталинию; близкие антиподы по прежнему контракту отклоняются. Полюса и размеры сильно искажены проекцией. Это основание для временного выбора карты, а не выбор финального движка глобуса.

Карточка раздельно показывает результат проверки всего перелёта, солнечное состояние назначения при прибытии, ближайшее найденное Солнце и видимые запасы. При заблокированном/неопределённом пути остатки не выдаются за успешное прибытие. После нового аэропорта планирование выполняется заново: неизвестная еда не используется для прогноза дальнейшей стоянки. Перелёт и автоожидание завершают пакет.

## Сохранение и журнал

`SpikeGame` — адаптер поверх `SimulationSession`, `ForecastTimeline`, `forecastPlan` и общего поиска стоянки. Физика не продублирована. Анимация только продвигает рассчитанный курсор; пауза фиксирует показанное состояние. Неполная наземная операция сохраняет передачи/расход, но не выдаёт флаг завершённой подготовки или обслуживания.

Сохранение партии версии 1 содержит закреплённые версии/seed, цепочку принятых сессий и активную сессию. Каждая сессия использует формат из #7. При загрузке вся цепочка проверяется и проигрывается до замены текущей партии; повреждённое или несогласованное сохранение её не меняет. После загрузки активное действие стоит на паузе. Браузерное сохранение — один слот в localStorage; файлы позволяют перенос между устройствами. Экспорт сохранения содержит приватные склады для восстановления; обычная проекция и журнал не открывают неизвестные запасы.

Журнал версии 1 содержит UTC начала/остановки, действия, подтверждения риска, отмены наземных действий, события, публичное итоговое состояние и версии/seed. Проверка экспортированного файла:

```sh
npm run build
npm run review -- /path/to/into-the-night-review.json
```

CLI начинает тот же сценарий, выполняет пакеты и остановки и сравнивает полный журнал/публичное состояние. UTC, действия, события и остальные поля сравниваются точно, независимо от часового пояса. Только итоговые топливо (кг) и расстояние (км) допускают абсолютную разницу до 10⁻⁹: тригонометрия Chrome/Node в проверенном прогоне отличалась примерно на 10⁻¹². Этот допуск проверки журнала не меняет физику, пороги безопасности или формат сохранений. Для журнала активного действия повтор останавливается на том же курсоре. Итог игры показывает время, расстояние, число перелётов и посещённых аэропортов, причину/UTC гибели, версии и seed.

## Проверки и ограничения

`npm run check` проверяет ядро, адаптер, приватность, подтверждения риска, паузу в полёте/стоянке, отмену наземной операции, сохранение всей партии, повтор журнала CLI и проекцию маршрутов. `npm run build:web` проверяет офлайн-сборку.

`npm run test:browser` требует установленный Chrome (`google-chrome`, либо `SPIKE_CHROME_PATH=/path/to/chromium`). Запускает построенную версию на локальном HTTP-сервере и выполняет реальные mouse/touch-вводы в Chrome: desktop 1280×900 и mobile 390×844, погрузка/перелёт, прогноз, пауза/сохранение/восстановление, месячная стоянка с остановкой, экспорт/сверка с CLI, подтверждение риска и итог. Проверка включена в GitHub CI. Это автоматическая проверка размеров и touch-ввода; ощущение игры и физические устройства остаются предметом рецензии владельца.

В текущем рабочем окружении запуск Chromium/локального HTTP ограничен системной песочницей; повторные запросы разрешения зависали, поэтому локальная ручная browser-проверка не объявляется выполненной. Результат проверки Chrome в CI указан в PR. Продакшен, полировка, полный каталог, устойчивость длинной истории за годы и финальный баланс вне границ spike. Настоящую локальную партию/сохранение не менять ради демонстрации известных маршрутов.
