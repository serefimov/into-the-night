# Игровой цикл без еды (#22)

Общий чистый модуль [mission.ts](../src/core/mission.ts) реализует выбор назначения, полёт, обязательные наземные операции и максимальную автозаправку. Один и тот же `MissionSession` доступен CLI и будущему интерфейсу. Кнопка «Полёт» в #23 будет вызывать этот API; отдельные команды подготовки/обслуживания/загрузки игроку не нужны.

Режим `airport-flight-v1`, симуляция `flight-cycle-1`, схема состояния 1 и события 1 отделены от прежнего survival. В состоянии нет еды, голода или бесконечного продовольственного запаса. Нет ручного ожидания, частичной загрузки по выбору или разрешения рискованного рейса. Время при изучении карты стоит; скорость анимации задаёт только частоту продвижения курсора, не физические длительности.

## Конфигурация и контрольные маршруты

Ядро принимает `MissionDefinition`: ID/версию сценария, seed, версии геоданных и складов, профиль самолёта, аэропорты, цель, правило финиша и начальные UTC/топливо/конечные склады. Конструктор копирует данные, проверяет координаты/ID/профиль/покрытие складов и готовность исходного аэропорта. Внешняя мутация определения не меняет сессию.

[westward-control.json](../data/scenarios/westward-control.json) — отдельный технический контроль, а не утверждение первого сценария научной кампании. Он воспроизводит [результат #21](WESTWARD_MISSION.md): Сантьяго → Крайстчерч/Сидней/Мельбурн → Перт → Кейптаун, старт 21 июня 2026 22:10 UTC, 100000 кг на борту, конечные игровые склады по 32000 кг. Зафиксированы профиль B788 и pinned-каталог. Исходные большие склады data/campaign/fuel.json не заменены. СПБ → Новосибирск остаётся отдельным исследованием; ядро не привязано к южным пунктам и не переносит в них научный сюжет.

В этом контроле цель завершается **после полного обслуживания/автозаправки** (`after_turnaround`). Ядро также поддерживает явное `arrival` для действительно конечной посадки. Переход определяется конфигурацией, не молчаливой заменой правил. Прибытие в аэропорт не означает получение знаний в удалённой лаборатории.

## API

| Вызов | Поведение |
| --- | --- |
| `new MissionSession(definition, options?)` | Создать сессию с собственными данными и параметрами солнечной проверки |
| `forecast(id)` | Получить `allowed`, причины и полный прогноз, не меняя время/ресурсы/журнал |
| `fly(id)` | Повторить тот же прогноз и принять только подтверждённый переход; начать выполнение в текущем UTC |
| `current()` | Текущие состояние и уже наступившие события; все остатки топлива публичны |
| `stateAt(utcMs)` | Просмотреть прошлое/будущее уже принятого полёта без изменения курсора или доставки событий |
| `stopAt(utcMs)` | Продвинуть выполнение до указанного UTC, вернуть новые события ровно один раз |
| `resume()` | Завершить уже принятый переход; следующий аэродром автоматически не выбирается |
| `availability()` | Явно проверить доступные направления/неопределённость/тупик, не продвигая время |
| `save()` / `MissionSession.restore(text, expectedDefinition?)` | Сохранить/проверить и восстановить сессию, включая середину фазы |

`forecast` и `fly` используют общий `forecastResearchFlight` из #21: ортодромию, профиль расхода/масс и непрерывную проверку всех фаз. Состояния «опасно» и «неопределённо» различаются, оба блокируют запуск. Неизвестный/текущий аэропорт, неоднозначная геометрия, непригодность, топливо/масса, Солнце и незавершённый рейс дают причины отказа без изменения сессии. Направление и широта сами по себе не запрещают полёт.

Прогноз содержит расстояние, UTC прибытия и конца оборота, расход, массы, остатки и заправку, фазы и результат солнечной проверки. Полёт не разрешается только на основании ночной посадки. Возвращаемые данные не являются ссылками на внутреннее состояние.

## Промежуточное состояние

Фазы: `departure`, `cruise`, `arrival`, `service`, `refuelling`; между полётами `planning`, терминально `won`/`dead`. `position`, расстояние, топливо, склады и активная фаза относятся к одному показанному UTC. Завершённый физический план предоставлен общим ядром; промежуточный расход распределяется по его фазам и профилю, итоговые границы закрепляются точными результатами перехода.

Во время подготовки заправки топливо ещё не передаётся. Затем оно непрерывно перетекает со скоростью профиля: борт увеличивается на фактически переданную массу, склад на неё же уменьшается. Передача ограничена свободной ёмкостью и остатком. При пустом складе/нулевой передаче нет дополнительной фазы заправки или цикла нулевых действий. Повторный визит не восстанавливает склад.

Конец полёта не означает раннюю победу, если требуются наземные фазы. `current()` показывает только наступившие события; `stateAt` может показать прогноз будущего до конца принятого плана, не меняя текущий журнал. `stopAt` не перематывает исполнение назад; для просмотра прошлого есть `stateAt`. Запрос времени после конца принятого плана ограничивается его концом: это не скрытое ожидание на земле.

Начальное солнечно опасное состояние сразу даёт реальное событие поражения от Солнца. Подтверждённый рейс уже проверен целиком, поэтому рискованный рейс не исполняется до поражения. Отсутствие безопасных направлений при замороженном времени — тупик, а не выдуманная смерть; `availability` также отдельно сообщает о непроверенных направлениях. Неопределённость Солнца не мешает признать направление заблокированным, если уже доказана нехватка топлива/масса/непригодность.

## Сохранения и события

Новый формат `into-the-night-mission`, версия 1. В нём находятся определение/версии/seed, параметры проверки, последовательность **принятых** назначений, UTC-курсор, курсор доставки событий и снимок. Восстановление проверяет checksum, версии, начальные данные, заново рассчитывает принятые переходы и сверяет текущий снимок/журнал. Оно создаёт новую сессию; повреждённый файл не заменяет живую партию. При переданном `expectedDefinition` требуется точное совпадение определения, включая склады/геоданные.

Восстановление пересчитывает историю от исходного состояния, затем возвращается к сохранённому курсору; оно не применяет заправку повторно к снимку. `newEvents` учитывает сохранённый курсор доставки. Старые survival-сохранения и несовместимые версии явно отклоняются. Общие функции JSON/checksum вынесены в serialization.ts с прежними экспортами из saves.ts; формат старого режима сохранён.

События имеют версию и последовательный номер: `mission_started`, `flight_started`, `arrived`, `refuelling_started`, `flight_completed`, `mission_won`, `mission_died`. Событие начала заправки включает её подготовку, начало передачи определяется временем профиля. Только наступившие события попадают в текущий журнал; повторное продвижение к тому же UTC не доставляет их снова.

## CLI и проверки

```sh
npm run build
npm run mission:cycle -- --path examples/mission-cycle/christchurch.json
npm run mission:cycle -- --path examples/mission-cycle/sydney.json
npm run mission:cycle -- --path examples/mission-cycle/melbourne.json
# Отказ прямого рейса: код выхода 2, состояние остаётся исходным.
npm run mission:cycle -- --path examples/mission-cycle/direct-blocked.json
# Пауза внутри первой заправки и сохранение:
npm run mission:cycle -- --path examples/mission-cycle/christchurch.json --stop-at 2026-06-22T09:45:00Z --save /tmp/mission.json
# Завершить принятый полёт; следующее назначение выбирается отдельно:
npm run mission:cycle -- --load /tmp/mission.json --resume
npm test
```

CLI — второстепенный инструмент повторения, его флаги не являются интерфейсом игры. Файл пути задаёт последовательные решения только после окончания предыдущего перехода; при паузе ещё не принятый остаток списка не попадает в сохранение. Вывод сокращает склады до посещённых аэропортов, API состояния содержит все точные публичные остатки. Неверный ввод даёт код 1, заблокированный выбор — 2.

Тесты сравнивают все три прохождения с независимыми сохранёнными результатами #21, проверяют атомарность отказа, непрерывное состояние, подготовку/перекачку, повторные визиты и пустые склады, границу финиша, неопределённость, тупик, версии/восстановление и однократную доставку событий. CLI воспроизводится в двух часовых поясах и продолжает частично выполненную заправку до того же итога. Новый интерфейс/глобус — #23, игровой браузерный spike и окончательная интеграция сохранений — #24.
