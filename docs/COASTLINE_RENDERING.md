# Чёткие берега глобуса (#54)

Береговая граница теперь задаётся Canvas Path2D, а не маской 1024×512.
`coastline.mjs` согласует d3-geo с камерой общего globeFrame; библиотека выполняет
сферическое отсечение, замыкание на горизонте и адаптивное разбиение дуг.
Затем путь ограничивается viewport. Проекция игрового маршрута и вся физика
по-прежнему принадлежат общему ядру.

Используется Natural Earth 1:50m, упрощённая **офлайн** с сохранением форм и
исправлением пересечений. Сырые 60 669 вершин требовали слишком долгого перестроения.
Источник, хеши и воспроизводимая обработка — [SOURCE.md](../data/geography/SOURCE.md).
Данные 1:110m сохранены для истории; аэропорты и физическая география не изменены.
Даже 1:50m остаётся обзорной картой, а не точной береговой съёмкой.

Путь берега и круг сферы кэшируются до изменения камеры, размера или DPR.
Числовой буфер нормалей/глубины освещения тоже переиспользуется. При новом UTC
меняются только два мягких растровых поля: цвет моря и суши. Их размер ограничен
560 px, но они рисуются через чёткую векторную маску; разрешение освещения не
определяет форму берега. Палитра, solarDirection и визуальная ширина терминатора
сохранены. Canvas, как прежде, использует DPR не выше 2.

`d3-geo` 3.1.1 выбран для корректного отсечения сложных полигонов/дыр и полярных
контуров вместо собственной неполной реализации spherical clipping.
Его зависимости d3-array 3.2.4 и internmap 2.0.3 закреплены lock-файлом. Сборка копирует
локальные ESM-исходники и ISC LICENSE в data/runtime/vendor, import map использует
относительные URL. CDN, отдельного картографического сервиса и нового bundler нет.

## Проверки

Node: совпадение проекции с общей камерой, полярные виды, невидимый полигон,
замыкание у горизонта, ориентация реальных материков/океана после импорта.
Chrome: 90 сочетаний пяти областей (Европа, Филиппины, ±180°, оба полюса),
масштабов 1/3/5, viewport 1280/390/320 и DPR 1/2. Проверяются реальные точки
суши/моря и полюса, синтетическая дыра в полигоне, отсутствие растянутой границы
(не более двух промежуточных физических пикселей на контрольном вертикальном
берегу), кэш при повторной отрисовке и неизменность сохранения от навигации.
Это конечный набор инвариантов, не полный перебор всех возможных полигонов.

Снимки `coast-*` находятся в артефакте globe-previews. Визуально сравнивались
одинаковые ракурсы с v0.1.0; отдельно проверялись 5×, острова, край сферы и полюса.
Полный существующий браузерный набор проверяет маркеры, маршрут, центрирование,
жесты, pause/resume, сохранения и оба Pages-пути.

## Измерения относительно v0.1.0

Один последовательный локальный прогон каждого варианта: Chromium 154.0.8037.57,
Node 24.19.0, один и тот же executor. Сессия на паузе, worker завершён, одинаковые
90 ракурсов/масштабов/DPR. Время перестроения включает focus + render; повторный
кадр — три синхронных draw на неизменной камере. Значения в мс, median / p95.
Это время CPU/Canvas-команд, не полная стоимость GPU/compositor и не гарантированный
FPS физического телефона. Мобильный viewport — эмуляция без CPU throttling.

| Viewport | Перестроение v0.1.0 | Перестроение #54 | Кадр v0.1.0 | Кадр #54 |
| --- | --- | --- | --- | --- |
| 1280×900 | 22,75 / 35,70 | 37,75 / 56,20 | 6,05 / 12,80 | 9,25 / 13,60 |
| 390×844 | 14,20 / 27,00 | 28,60 / 43,90 | 3,70 / 8,20 | 5,55 / 8,60 |
| 320×844 | 13,70 / 21,00 | 27,80 / 48,40 | 3,10 / 4,30 | 4,40 / 7,40 |

Более подробная география стоит дороже прежнего растра; ускорение не заявляется.
Для сравнения, сырая 1:50m давала median перестроения 80,35 / 74,35 / 66,70 мс
соответственно; поэтому она не вошла в рендер без предварительной обработки.
В контроле клавиатурного поворота (по одному событию на viewport/DPR) задержки
до следующего готового кадра были 25,7–75,2 мс у v0.1.0 и 33,7–74,4 мс у #54.
Такой малый набор не доказывает улучшения latency. Touch/mouse проверяются также
существующими сценариями. Нужна отдельная проверка на физическом телефоне;
во время непрерывного вращения возможен меньший FPS, чем у упрощённого v0.1.0.

## Воспроизвести

```sh
npm ci
npm run build:web
COAST_ONLY=1 COAST_BENCHMARK=1 SPIKE_CHROME_PATH=/usr/bin/chromium npm run test:browser
# Числа: .build/coast-metrics.json; сравнимые снимки: .build/previews/coast-*.png
```

Для baseline собрать отдельное worktree v0.1.0. Из его рабочей директории запустить
**тот же** scripts/test-browser.mjs новой ветки через абсолютный путь, с
`COAST_ONLY=1 COAST_BASELINE=1 COAST_BENCHMARK=1 SPIKE_CHROME_PATH=/usr/bin/chromium`.
Сервер запускается из cwd и обслуживает старую сборку, проверочный runner остаётся
одинаковым. Baseline не проходит новые assertions Path2D/дыр: он используется
для измерений и снимков, а не объявляется прошедшим требования #54.
