# Окна отправления (#57)

Поиск находится в `src/core/departure-window.ts`, API сессии —
`departureWindowSteps(id)` (порционный генератор) и `departureWindow(id)`
(синхронная версия для CLI/проверок). Он не изменяет партию.

Сначала проверяется немедленный переход. При постоянном препятствии (топливо,
масса, пригодность, геометрия) ожидание не предлагается. Для солнечных и
неопределённых ограничений перебираются начала перехода с шагом **15 минут**
до **24 часов** от текущего UTC. Для каждого проверяется вся стоянка общим
`forecastMissionWait` из #25, затем весь `forecastMissionFlight`, включая
подготовку/перекачку, перелёт, посадку и обязательное обслуживание. На стоянке
ресурсы не меняются, поэтому будущий расчёт использует те же остатки.

Это первая подтверждённая точка конечной сетки, а не математически самое раннее
окно. Более узкие интервалы между точками могут быть пропущены. Если более
ранняя точка была неопределённой, найденный вариант явно сохраняет этот признак.
`not_found` означает только отсутствие подтверждённого варианта на проверенной
сетке до горизонта/опасной границы, а не невозможность любого будущего рейса.
Опасный восход на исходном аэродроме обрывает поиск: перепрыгнуть через него
нельзя. Неопределённая стоянка также не разрешает ждать. Выход за диапазон
модели отмечается как ограничение диапазона.

Общий бюджет солнечных вычислений, включая немедленный прогноз, по умолчанию
100000; используются существующие SearchOptions с допустимым диапазоном
4..1000000. Результат содержит число кандидатов/вычислений, горизонт, шаг,
причину ограничения и неопределённость более ранних кандидатов. Генератор
уступает управление после каждого отвергнутого кандидата, не создавая второго
таймера симуляции.

Worker сначала проверяет немедленные рейсы всего каталога, затем окна каждого
направления, независимо от камеры и группировки. Выбранное направление получает
приоритет. Ответы привязаны к поколению и planningKey; при смене UTC/сессии старые
ответы игнорируются. Резервный расчёт использует тот же генератор с уступкой
управления. Результаты окон передаются небольшими пакетами без копий всех
складов в каждом UI-прогнозе. В сводке раздельны немедленные рейсы, найденные
варианты после ожидания и прогресс окон.

Карта показывает ◷ у направлений/групп с подтверждённым ожиданием, независимо
от цвета. Карточка различает поиск, неопределённость, постоянный запрет и
ненайденное окно. Она показывает длительность ожидания, UTC начала перехода,
фактический вылет после заправки/подготовки и прибытие. «Ждать до вылета»
останавливает время на **начале перехода**; подготовка не выполняется во время
стоянки, а начинается после отдельного подтверждения «Полёт».

`waitForDeparture(id,startUtcMs)` заново проверяет стоянку и будущий переход
перед принятием действия. Кэш worker не является разрешением на физическое
действие. Пауза/«Остановить ожидание» используют контроллер #25; отмена оставляет
фактический UTC и запускает новый прогноз. При завершении ожидания время
останавливается, автоматического вылета нет. Немедленные рейсы и их скорость
воспроизведения не изменены.

Сохранение целевого ожидания — envelope **v5**: в действии ожидания сохраняется
назначение, исходный конец и фактическая остановка. При загрузке заново
проверяются и стоянка, и будущий переход, выбранное назначение восстанавливается,
воспроизведение остаётся на паузе. v3 (только перелёты) и v4 (ожидание без
назначения) продолжают читаться и записываться. Схема физического состояния и
версии событий остаются 3; ресурсы и их конечные склады не восстанавливаются.
Экспорт читается общим CLI.

Политика no_routes из #25 сохранена: только постоянные препятствия всех
направлений доказывают тупик. Частичная/ограниченная/неопределённая проверка
окон и даже полный перебор конечной сетки не объявляют поражение от отсутствия
маршрутов. Исторические свидетельства v0.1.0 не переписаны.
