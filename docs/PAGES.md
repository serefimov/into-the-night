# GitHub Pages

Сайт: https://serefimov.github.io/into-the-night/. Корень предлагает два раздела:

- `dev/` — только последняя успешная сборка `main` и каждой ветки с открытым PR этого репозитория. Ветки чужих forks не публикуются.
- `release/` — все выпуски, созданные стабильными тегами `vX.Y.Z`.

Статус готовности игры не меняется от публикации: сейчас это экспериментальный трёхаэропортовый spike для рецензии.

## Однократная настройка владельцем

1. Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. Settings → Environments → **github-pages** → Deployment branches and tags: **No restriction**. Dev публикуется из рабочих веток/PR, release — из тегов; ограничение только main или v* блокирует часть запусков.
3. Actions должны быть разрешены. Если используются rulesets, разрешить workflow создавать/обновлять служебную ветку `pages-archive`. Job архивирования запрашивает `contents: write` и `pull-requests: read`; job публикации — `pages: write` и `id-token: write`.

Личный токен и Secrets не нужны: используются `GITHUB_TOKEN` и OIDC. GitHub-коннектор для работы с репозиторием не предоставляет изменение административных настроек Pages/окружений. Workflow не меняет эти настройки.

После merge PR публикация запускается автоматически. Если настройки включены позже, повторите последний запуск «Публикация dev и release» либо запустите его через Actions → Run workflow на main. Ручной запуск синхронизирует и публикует уже сохранённый архив; новую игру собирают push и открытие/обновление PR.

## Dev: одна сборка на открытую ветку

Push в рабочую ветку и открытие/обновление PR запускают проверки ядра/CLI, независимые проверки физики, сборку и Chrome desktop/mobile под вложенным путём. Неуспешная проверка оставляет прежнюю успешную сборку.

Для `main` постоянный адрес: `dev/bWFpbg/`. Для другой ветки — `dev/<base64url UTF-8 имени ветки>/`. Имя ветки показывается обычным текстом в каталоге. Кодирование делает безопасными имена с `/`, пробелами и Unicode. Ссылка не привязана к коммиту: новая успешная сборка заменяет прежнюю, а каталог показывает версию, коммит и UTC сборки.

Закрытие/merge PR удаляет dev-сборку его ветки, даже если ветка ещё не удалена в GitHub. Удаление ветки, ежедневная синхронизация и ручной запуск также обновляют каталог. При повторном открытии PR появится новая проверенная сборка. Ветки без открытого PR не представлены, кроме main. Служебная ветка `pages-archive` не является игровой сборкой.

Раздела «все сборки» нет. Предыдущие dev-файлы удаляются из текущего дерева архива и сайта. История Git не переписывается и может содержать старые файлы. Выпуск релиза не удаляет актуальные dev-сборки открытых веток.

## Выпуск по тегу

Версия продукта хранится в `VERSION`, сейчас `0.1.0-alpha.1`. Это версия опубликованной игры, отдельная от технической версии npm-пакета и версий симуляции/сценария. Допускаются `X.Y.Z` и суффиксы `alpha`, `beta`, `pre`, `rc` с необязательным номером. Изменения разработки описываются в `CHANGELOG.md` под «Не выпущено».

1. В отдельной задаче подготовьте PR: `VERSION` → `X.Y.Z`, изменения → раздел `## X.Y.Z` в changelog.
2. Дождитесь CI и влейте PR в main.
3. Создайте тег `vX.Y.Z` на коммите main. Можно через GitHub Releases → Draft a new release → новый тег, Target: main → Publish release.
4. Проверьте workflow и откройте `release/X.Y.Z/`.
5. Следующую разработку ведите с будущей версией и суффиксом в VERSION.

Тег обязан совпадать со стабильным VERSION, иметь запись в changelog, указывать на проверяемый checkout и находиться в истории main. Prerelease-теги и обычный push стабильной версии не создают release. Коммит релиза, лицензия, VERSION, changelog и все байты сборки сохраняются. Повторная публикация того же содержимого допустима; изменённый тег или содержимое по существующему адресу отклоняются. Все релизы остаются на сайте; отсутствие тегов означает пустой список релизов. В этой задаче релизный тег не создаётся.

## Архив и параллельные запуски

Как в incredible-universe, полный сайт хранится в `pages-archive`, поскольку Pages заменяет весь сайт при деплое. В архиве — последние dev-папки, релизы и служебные отметки последних запусков. Служебные отметки не копируются на сайт.

Архив записывается обычным push без force. При конкурентной записи скрипт повторно читает архив и открытые PR, объединяет изменения и повторяет push. GitHub run ID не позволяет более старому запуску откатить dev-ветку; отметки удаления не дают ему вернуть закрытую ветку после её повторного открытия. Ошибка API при получении PR прекращает публикацию, а не превращает каталог в пустой.

Только деплой стоит в общей очереди `github-pages`. Каждый проверенный релиз/сборка до очереди уже сохранён; job деплоя читает текущий архив внутри очереди. Даже если GitHub заменит ожидающий деплой более новым, выпуски не теряются. Не удаляйте/редактируйте архив вручную.

В каждой папке игры есть относительный вход `index.html` → `web/index.html`; модули и контрольные JSON также используют относительные пути. Игра работает под `/into-the-night/dev/.../` и `/into-the-night/release/.../`, не требует доменного корня или отдельного backend. Экспортированное файловое сохранение можно перенести между сборками с совместимыми версиями; localStorage общий для origin, поэтому для рецензии разных версий лучше скачивать отдельные файлы.

## Проверки

```sh
npm ci
npm run check
npm run build:web
npm run test:browser
SPIKE_TEST_BASE=/into-the-night/release/0.1.0/ npm run test:browser
```

Проверки публикации включены в `npm run check`: замена dev, закрытие/повторное открытие PR, запоздалый запуск, immutable release, валидация тегов/истории main, постраничное чтение PR, исключение forks и конфликтующий push в локальный bare-репозиторий. Chrome в CI проходит полный игровой сценарий с mouse/touch, включая загрузку модулей и данных под вложенным путём. Локально Chromium/HTTP могут быть ограничены рабочей песочницей; результат hosted CI и первого Pages-деплоя приводится в PR.
