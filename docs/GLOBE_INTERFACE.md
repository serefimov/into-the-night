# Глобус и карточка аэродрома (#23)

Новый главный экран — `web/flight/index.html`; корень dev/Pages-сборки открывает его. Предыдущий survival остаётся по `web/index.html`. Это интерфейс общего цикла #22 на подтверждённом контрольном маршруте Сантьяго → Кейптаун. Он не переносит научную кампанию в эти пункты и не утверждает неподтверждённый СПБ → Новосибирск.

## Действия игрока

Перетаскивание вращает Землю, колесо/щипок меняет масштаб. Кнопки `+`/`−`, возврат к самолёту и показ цели — только навигация. С клавиатуры доступны стрелки/масштаб и кнопки меток. Выбор метки открывает карточку, не запускает рейс и не меняет UTC/ресурсы.

Карточка показывает название/коды, расстояние, запас аэродрома, длительность и UTC прибытия, топливо перед вылетом и после посадки, объём/длительность дозаправки на исходном аэродроме, UTC отправления и завершения обязательных операций. Запас в назначении показывается отдельно и после посадки не расходуется до следующего решения. В ней одна маршрутная команда — **«Полёт»**. Недостаток топлива/масса, непригодность, Солнце и неопределённость дают причину и выключенную кнопку. Солнце на глобусе относится к текущему UTC; возможность вылета учитывает будущую траекторию и наземные фазы, а не только освещение назначения.

После подтверждения включается воспроизведение принятого перехода; доступны пауза/продолжение. Один переход занимает примерно 45 секунд экранного времени, физические длительности не меняются. Возобновление сохраняет прежний темп. Самолёт, освещение, календарь, склады и фаза показывают один UTC общего ядра. Между полётами время стоит. При выполнении камера следует за самолётом, пока игрок не начнёт самостоятельную навигацию; кнопка возврата снова показывает самолёт.

Метки имеют области касания 44×44 CSS px. В #43 введён отдельный экранный layout `web/flight/marker-layout.mjs`: обзорный бюджет 7–24 метки зависит от площади видимой Земли и экрана, при масштабе ≥2.2 — 12–56. Это максимум, не обязательное заполнение. Обычные аэропорты объединяются по экранному расстоянию до попадания в бюджет; на обзоре нет их подписей и россыпи чисел/красных крестов. Доступные группы имеют отметку ✓, остальные спокойный +; детали/численность раскрываются при приближении. Недоступные одиночные аэропорты на обзоре — небольшие нейтральные точки.

Выбранный аэропорт, текущий аэродром, цель и концы принятого рейса получают приоритет. Обычные метки не закрывают самолёт; он рисуется поверх маршрута/меток. Подписи выбираются без взаимного наложения и с учётом кнопок/легенды/воспроизведения. Если приоритетный маркер нужно сдвинуть из-под контрола, его истинное положение отмечается соединительной линией. При близком соседстве сохраняется группа с приоритетной меткой. Группа приближает область своего аэропорта; на максимальном масштабе открывает список всех её участников, включая непригодные/заблокированные. Фокусирование любой записи полного каталога раскрывает её как выбираемую метку или участника группы. Изменение результатов worker меняет статус, не переставляет группы.

Подсказка на карте объясняет приближение для дополнительных аэропортов. Видимый набор не является списком всех рейсов. Полный каталог, запасы и worker не фильтруются layout; глобальная сводка/исход #42 должны использовать весь каталог независимо от камеры. Эта задача не реализует #42. Жест длиннее 8 CSS px и двухпальцевое движение не выбирают метку; камера/масштаб не меняют сессию.

## Почему Canvas-глобус

Выбран ортографический глобус на Canvas без внешнего движка/CDN: мировые маршруты не разрываются на ±180°, полярные виды используют ту же трёхмерную нормаль. Он работает без WebGL и внешнего картографического сервиса. Береговая линия Natural Earth 1:110m хранится в репозитории, [источник/commit/Public Domain](../data/geography/SOURCE.md). Растровая поверхность ограничена 560 px по большей стороне для мобильной отрисовки, метки и линии остаются в разрешении экрана. На крупном масштабе это обзорная география, не схема ВПП.

`src/core/globe.ts` содержит только проекцию/обратное преобразование и обрезку видимой полусферы. Маршрут сэмплируется через общий `greatCircle`/`greatCirclePosition`, неоднозначные антиподы не получают выдуманную линию. Поверхность использует `solarDirection` общего солнечного модуля. Сглаженная граница освещения — визуальный эффект; допустимость определяет строгий прогноз `MissionSession`.

Предварительные прогнозы выполняются в модульном Web Worker из снимка той же сессии. Результаты относятся к одному состоянию планирования; при запуске/окончании рейса поколение результатов меняется, старые ответы игнорируются. Карточка и подтверждение вызывают актуальный общий API. Если фоновая проверка недоступна, выбор метки продолжает проверяться локально; неизвестные метки не становятся зелёными по предположению.

Данные для браузера генерируются `scripts/build-flight-data.mjs` из версионированной конфигурации #22: сокращаются только метаданные аэропортов, профиль/координаты/пригодность/запасы сохраняются. Генерируемый `data/runtime/mission.json` не коммитится; сборка создаёт его заново. Все URL относительные, включая worker, JSON и модули ядра, поэтому работают dev и вложенные теговые Pages-адреса.

## Воспроизведение и границы

```sh
npm run dev
# либо статическая сборка:
npm run build:web
npm run serve:web
npm run check
npm run test:browser
SPIKE_TEST_BASE=/into-the-night/release/0.1.0/ npm run test:browser
```

Node-тесты проверяют проекцию/обратное преобразование на шве и у полюсов, обрезку дуг и независимость выбора/паузы от физического темпа. Chrome-сценарий desktop/mobile выполняет реальные mouse/touch-жесты, выбирает метки/группы, проверяет опасный прямой рейс, подтверждает западный, останавливает выполнение, проверяет частичную заправку и завершает цепочку до Кейптауна. Контролируется отсутствие числовых форм и горизонтального переполнения, совпадение UTC интерфейса/рендера/ядра, фоновый прогноз и география. Проверки повторяются на вложенном Pages-пути; прежний браузерный сценарий остаётся отдельной регрессией. Дополнительно проверяются бюджет, полный worker-каталог (1183 записи), плотная Европа при приближении/отдалении, области касания и неизменность сохранения. Node-проверка фокусирует каждый аэропорт, включая совпадающие координаты, проверяет состав групп и препятствия/подписи. Скриншоты обзора и плотной области desktop/mobile сохраняются артефактом CI `globe-previews`.

Сохранение/восстановление через интерфейс, перезапуск, экспорт и полноценная рецензия playable spike — #24. Ядро их поддерживает, но текущий экран начинает контрольную партию заново при перезагрузке страницы. Еда, ручное ожидание и сезонные главы сюда не включены.
