# Модель Солнца и проверка версии meeus-noaa-1

## Контракт

Общее ядро TypeScript в `src/core` работает в браузере и Node без DOM, сети и локального часового пояса. Версии алгоритма и конфигурации находятся в `SOLAR_MODEL`. Входное время — миллисекунды Unix epoch UTC; длительности будущего симулятора — секунды, расстояния — км, топливо — кг, еда — человеко-часы. Координаты и высота — градусы, долгота положительна к востоку.

Поддерживаемый диапазон: **2020-01-01T00:00:00Z включительно — 2041-01-01T00:00:00Z исключительно**. Вне него расчёт отклоняется, а не экстраполируется. CLI принимает только явное UTC `YYYY-MM-DDTHH:mm:ss[.sss]Z`, проверяя календарь; неявное местное время и переполнение даты запрещены.

`solarDirection(utcMs)` возвращает единичное направление геоцентрического центра Солнца в земной системе: x — экватор/Гринвич, y — экватор/90° E, z — северный полюс. `solarExposure(position, utcMs)` вычисляет q=n·s, высоту asin(q) и `safe`. Безопасно строго q<0; q>=0, включая касание горизонта, опасно. Допуск безопасности не вводится. На полюсах нормаль задана точно, без зависимости от долготы.

Нет рефракции, рельефа, солнечного диска, топоцентрического параллакса или высоты самолёта. Аберрация и приближённая нутация включены в солнечное направление и согласованную сидерическую систему. Эти астрономические поправки не меняют игровую границу геометрического горизонта.

## Алгоритм и лицензии

Использованы низкопорядковые формулы солнечной долготы/аномалии, уравнения центра и наклона эклиптики из алгоритма Meeus/NOAA; из видимых прямого восхождения и склонения направление вращается на Greenwich apparent sidereal time. Склонение меняется с датой, включая месяцы и сезоны. UTC приближает UT1 и время эфемериды; DUT1, отдельная TT-шкала и таблицы leap seconds не используются. Это ограничение включено в сравнение с независимым эталоном.

Источники формул:

- Jean Meeus, *Astronomical Algorithms*, 2nd edition (1998), главы о юлианской дате, звёздном времени и солнечных координатах.
- [NOAA Solar Calculation Details](https://gml.noaa.gov/grad/solcalc/calcdetails.html) и связанные расчётные таблицы. NOAA отдельно описывает ограничения приближений и рефракционные правила своего калькулятора; его восходы напрямую не используются как эталон геометрической границы.

Реализация написана для проекта и распространяется по GPL-3.0-only; код сторонних калькуляторов не скопирован. TypeScript 5.9.2 — инструмент разработки под Apache-2.0. Astronomy Engine 2.1.19 — независимый инструмент генерации эталонов под MIT, не runtime-зависимость ядра. Его лицензия сохранена в [ASTRONOMY_ENGINE_LICENSE.txt](ASTRONOMY_ENGINE_LICENSE.txt).

## Независимые эталоны

В `test/fixtures/solar-reference.json` сохранены **1346** направлений: ежемесячные моменты в 00/06/12/18 UTC за каждый год 2020–2040, дополнительные даты около равноденствий/солнцестояний и края диапазона. Данные не вычисляются проверяемым ядром.

Генератор использует [Astronomy Engine v2.1.19](https://github.com/cosinekitty/astronomy/tree/v2.1.19), commit `61dc07020aaa6885d2c7f688a4d82beaf6edb9ef`. Его эфемерида на основе VSOP отличается от низкопорядковой модели проекта. Эталон: `GeoVector(Sun, aberration=true)` в EQJ → `Rotation_EQJ_EQD` → вращение на минус `SiderealTime`. Это геоцентрический центр, без рефракции и параллакса; преобразование учитывает внутреннюю DeltaT/TT и apparent sidereal time эталона. Числовые fixtures созданы для проекта и лицензированы GPL-3.0-only; сведения об источнике включены в JSON.

Обычные проверки полностью офлайн после установки зависимостей:

```sh
npm ci
npm run check
npm run validate:solar
```

Повторная генерация также не требует сети после установки Astronomy Engine:

```sh
npm run fixtures:solar
git diff --exit-code -- test/fixtures/solar-reference.json
```

## Результаты

Машиночитаемый отчёт: [solar-validation.json](solar-validation.json). Воспроизведение: `npm run build && npm run validate:solar` (JSON без npm-заголовков: `node scripts/validate-solar.mjs`).

Максимальная ошибка направления на выборке — **0.008388755°** (2023-01-15 00:00 UTC), ниже ориентира 0.05°. Максимальная ошибка высоты на сетке широт/долгот: 0.008306° в обычных широтах, 0.005281° на высоких широтах и 0.002867° на полюсах. Проверены оба полушария; это измерения на выборке, не математическая оценка для каждого момента непрерывного диапазона.

Для восьми геометрических восходов отдельно вычислены эталонный и модельный корни в заранее найденных часовых скобках. Бисекция с шагом до 1 миллисекунды — только утилита отчёта: она не реализует надёжный поиск первого события на произвольном маршруте или за 370 суток. Такой поиск относится к #4 и #6.

| --- | ---: | ---: |
| Экватор, март | 0° | +1.211 |
| Гринвич, июнь | 51.4779° | +0.736 |
| Тромсё, март | 69.681389° | -0.166 |
| Лонгйир, первый найденный февральский восход | 78.246111° | -7.180 |
| Около северного полюса | 89° | -55.990 |

| Северный полюс, сезонный восход | 90° | -455.838 |
| Южный полюс, сезонный восход | -90° | +233.866 |

У полюса Солнце пересекает горизонт медленно: при малой производной высоты небольшая угловая ошибка даёт смещение на минуты. Нельзя обещать физическую точность восхода до секунды из углового допуска 0.05°. Будущий поиск должен локализовать событие выбранной **игровой модели** до секунды; прогноз и исполнение обязаны использовать её же. Если требуется более точное совпадение с эфемеридой в полярных районах, нужно заменить/уточнить модель и заново версионировать результаты, а не скрывать ошибку допуском безопасности.

Ни один из результатов не подтверждает безопасность маршрута, проходимость сценария или баланс ресурсов.

## Проверки окружения

Проверено на Node 24.19.0 и npm 11.9.0: строгая проверка типов TypeScript 5.9.2, сборка, семь тестов и CLI-проверка в четырёх процессных часовых поясах (UTC, Europe/Oslo, America/New_York, Pacific/Auckland), неверная календарная дата и код выхода. Исходные проектные документы сохранены.

В рабочем окружении npm-сеть недоступна. Для локальной проверки компилятор 5.9.2 получен через GitHub из cdnjs, стандартные TypeScript-декларации — из Deno v2.5.2, Astronomy Engine — из своего тега v2.1.19. Временные инструменты остаются в игнорируемом node_modules; они не публикуются. Lockfile фиксирует официальные npm-версии и адреса дистрибутивов. Проверка чистой установки из реестра выполняется workflow Checks, её результат следует оценить в PR отдельно от локальных численных тестов.
