# Дозаправка перед выбранным рейсом (#39)

После посадки самолёт проходит обязательное обслуживание и ждёт следующего решения с оставшимся топливом. Выбор аэропорта ничего не расходует. Кнопка «Полёт» принимает целиком проверенную последовательность: дозаправка здесь → отправление → ортодромия → посадка → обслуживание там. Карточка показывает нужную дозаправку, длительность, топливо перед вылетом/после посадки, отправление и конец операций; склад назначения показан отдельно.

Текущий старт браузера/CLI — [первый западный этап СПБ → Новосибирск](ACADEMIC_WESTWARD.md). Приведённые ниже южные цепочки остаются отдельным контролем правила #39.

## Количество и безопасность

Требуемое бортовое топливо = расход отправления + крейсерский расход + расход посадки + расход обязательного обслуживания в назначении + резерв профиля. Дозаправка = max(0, требуемое − уже на борту). Для текущего B788-reference-v1 резерв **5000 кг**, уже существовавший в профиле: это базовое правило реализации, не новый отдельно утверждённый владельцем численный параметр. Резерв остаётся после обслуживания. При `targetCompletion: arrival` обслуживание конечной посадки не добавляется.

Проверяются ёмкость, конечный склад исходного аэропорта, взлётная/посадочная массы, пригодность полосы и непрерывная солнечная безопасность всех фаз, в том числе подготовки/перекачки **до вылета**. Нехватка топлива или опасность блокирует весь рейс без частичного списания и сдвига UTC. Нулевой объём не создаёт фиктивную подготовку. Лишнее уже имеющееся топливо не сливается: если оно делает посадку слишком тяжёлой, причина честно остаётся в прогнозе.

Источник расчёта — src/core/mission-flight.ts, общий для MissionSession, CLI, worker и карточки. Пауза показывает фактическую передачу из исходного склада; восстановление не выполняет её второй раз. Событие `flight_committed` относится к подтверждению, `flight_started` — к отправлению после дозаправки. Исторический контракт #39 — airport-flight-v2 / flight-cycle-2 и формат 2. Текущий контракт исходов #42 — airport-flight-v3 / flight-cycle-3, состояние/события/save 3; физическое правило дозаправки сохранено, старые сохранения v2 явно отклоняются ([подробнее](ROUTE_OUTCOMES.md)). Сохранения mission v1 явно отклоняются, старый survival остаётся отдельным режимом.

## Контроль v2 и игровые настройки

Конфигурация [westward-control-v2.json](../data/scenarios/westward-control-v2.json): SCEL, **21 июня 2026 21:50 UTC, 30 т на борту**. Конечные склады по **64 т**, в исходном SCEL **100 т**, seed westward-control-v2, stockVersion departure-stocks-v2. Цель FACT — после обслуживания (`after_service`), без заправки для невыбранного продолжения.

Это явное изменение игровых параметров. Старые 100 т на борту сами блокировали короткие посадки; 30 т сохраняют стартовую загрузку без скрытого слива. Старый склад 32 т не покрывает самостоятельную дозаправку Перт → Кейптаун (около 58.48 т), когда лишнее больше не везётся с предыдущей остановки. 64 т покрывают этот рейс, оставаясь конечным запасом; 100 т в SCEL поддерживают несколько длинных первых направлений. Старт сдвинут на 20 минут раньше для исходной дозаправки. Скорость, расход, массы, Земля, Солнце и реальный каталог не изменены.

[Новый отчёт](departure-fuel/report.json) содержит SHA-256 входов, загрузки/остатки/UTC каждой фазы, уточнённую непрерывную проверку (0.05 с) и повтор обычными параметрами. Все три западные цепочки подтверждены:

| Из SCEL через | Расстояние | Готовность в FACT, UTC 23 июня |
| --- | ---: | --- |
| Крайстчерч → Перт | 23053 км | 05:17:37 |
| Сидней → Перт | 23307 км | 05:37:10 |
| Мельбурн → Перт | 22685 км | 04:49:17 |

На финише остаётся резерв около 5 т; склад FACT не тронут. Прямой восточный рейс SCEL → FACT солнечно опасен в полёте. Полярный день на Шпицбергене непрерывно подтверждён 21–23 июня. После длинного первого рейса физически разрешён короткий NZCH → NZAA (745 км) с небольшой дозаправкой; полный бак нарушал бы посадочную массу.

Это технические контрольные цепочки, не исчерпывающий поиск и не утверждение научной кампании/первого этапа СПБ → Новосибирск (#21). Старые westward-control.json, отчёты mission-research/campaign-research и их правила максимальной заправки сохранены без перезаписи результатов; прежние команды сверки продолжают работать.

```sh
npm run build
npm run research:departure
npm run validate:departure
npm run mission:cycle -- --definition data/scenarios/westward-control-v2.json --path examples/mission-cycle/christchurch.json
npm run check
npm run test:browser
```

Для осознанного обновления эталона: `npm run research:departure -- --write`, затем проверить diff входов/чисел. Еда и ручное ожидание не добавлены. Явное поражение при отсутствии маршрутов — #42, снижение плотности меток — #43.
