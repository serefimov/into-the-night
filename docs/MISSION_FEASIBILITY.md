# JFK → Heathrow: исследование #21

## Результат и точка решения

При принятых условиях **не найден даже допустимый первый ход**. Для 21 июня 2026 года расчёт исключает все 101 направления из JFK в предварительно отобранные аэродромы текущего каталога, причём для всего допустимого начального топлива, а не только для одного бака. Ещё 5 площадок не имеют подтверждённой геометрической пригодности и не разрешены как ходы.

Это ограниченный вывод для snapshot из 107 аэропортов, reference-профиля B788 и фиксированных аппроксимаций #20. **Это не доказательство невозможности реального перелёта**: каталог неполон, расход и наземные фазы приближённые, эксплуатационная пригодность не подтверждена AFM. Проверка показывает, что зафиксировать текущие условия как уже проходимую игровую миссию нельзя.

Подтверждённый playable-сценарий и успешный маршрут не созданы. Переход к #22–#24 требует решения владельца об условиях/дальнейшем исследовании; физика и исходные данные не подгонялись. Исторические результаты OSL/TOS/LYR сохранены без изменений.

## Входные данные и воспроизведение

Используется [профиль и каталог #20](MISSION_DATA.md), версия профиля 1, B788-reference-v1, каталог 1, snapshot OurAirports 11e4de2834aff6ab54c1f8fc89b8679ea3d08418. Конечные публичные склады — seed jfk-heathrow-research-v1. В отчёте есть SHA-256 профиля, геоданных, метаданных каталога и складов.

Исследовательская дата — 2026-06-21. Геометрический восход JFK по общему модулю — примерно **09:29:32.57 UTC**, исследовательский старт — **08:29:32.57 UTC**, ровно за 3600 секунд. Дробные миллисекунды сохранены, ISO-строки округлены только для чтения. Стартовое состояние готово к фазе отправления: она занимает 900 секунд и включает время профиля, не исполняется бесплатно. Отдельная старая preparation не добавляется второй раз.

Контрольный прогон использует 50000 кг на борту до фазы отправления. Это reference-загрузка для воспроизведения отказов, **не утверждённое начальное топливо новой игры**. Отдельная интервальная проверка охватывает все физически допустимые загрузки для каждого первого аэродрома.

```sh
npm ci
npm run build
npm run research:mission -- --research
npm run validate:mission
npm run research:mission -- --path examples/mission-research/direct-london.json
npm run research:mission -- --path examples/mission-research/northern-attempt.json
npm run research:mission -- --path examples/mission-research/western-attempt.json
```

Последние три команды воспроизводят **отклонённые попытки**, не маршруты-победители; код выхода 2 означает заблокированный ход. Ошибка аргументов/данных — код 1. Принимается JSON-массив ID аэродромов, каждый ход заново прогнозируется и исполняется одним общим переходом; до отклонённого выбора партия не меняется. Код 0 у --verify означает совпадение отчёта, а не возможность выиграть.

Пересчёт артефактов: `npm run research:mission -- --research --write`. Сводка — [report.json](mission-research/report.json), полные данные направлений разделены по регионам в docs/mission-research. --verify загружает все части и сверяет полный результат.

## Общие расчёты, фазы и финиш

src/core/mission-research.ts использует существующие greatCircle и checkRoutePhaseSafety, тот же солнечный алгоритм и поиск интервалов. Скорость B788 передаётся длительностью круиза; кривизна траектории берётся из общей проверки фазы. Второй модели Солнца нет. Расход, масса и заправка — общий aircraft.ts из #20. Это исследовательский общий переход, ещё не UI/сессии нового игрового режима.

Фазы промежуточного хода: отправление 900 с → ортодромия со скоростью 870.44 км/ч → прибытие 900 с → обслуживание 600 с → подключение и максимальная передача топлива. Никакого ручного ожидания/частичной заправки. Время выбора стоит; конечные склады передаются в состоянии, повторные посещения не восстанавливают их. При недопустимом выборе возвращается отказ и next=null, вход не мутируется.

В Heathrow финиш — **безопасный конец фазы прибытия, до ненужных обслуживания и заправки**. Конечная точка входит в солнечную проверку: q>=0 на этом UTC исключает победу. Сначала безопасность/ресурсы и только затем won. Дозаправка целевого аэропорта после завершения миссии не является дополнительным требованием.

Отдельно проверяются достаточность топлива с reference-резервом, взлётная и посадочная масса, пригодность, Солнце. При недостаточном топливе полный физический наземный переход невозможен: поле solarScope явно указывает, если диагностирована лишь геометрия полёта без обещания безопасной автозаправки. Неопределённый интервал не объявляется смертью или безопасным ходом.

## Почему перебор топлива не помогает в текущем каталоге

Для фиксированного первого назначения пусть B — расход полёта, Z — безтопливная масса, C — ёмкость, R — reference-резерв. Законный начальный запас лежит в замкнутом интервале:

- Fmin = B + R;
- Fmax = min(C, MTOW − Z, MLW − Z + B).

Если Fmin>Fmax, интервал пуст. Иначе геометрия и время полёта не зависят от F. Чем выше F, тем больше остаётся после посадки и тем короче обязательная заправка. Для конечного склада S передача A(F)=min(C−(F−B), S) не возрастает с F; время наземного пребывания также не возрастает. Поэтому проверка Fmax даёт **оптимистическую нижнюю границу времени заправки**. Если даже её путь/наземный префикс содержат достоверный q>=0, все меньшие законные F также отклоняются. Этот вывод не применяется к indeterminate.

Граничные массы считаются double; Fmax может дать расхождение последнего разряда в строгой проверке массы. Он используется только как оптимистическая граница для солнечного исключения, а не как разрешённая загрузка или свидетель проходимости. Никакого epsilon для разрешения перегруза не вводится.

После допустимой посадки бортовое топливо не превышает MLW−Z=46365 кг. В рассматриваемом профиле полный бак 100964.8 кг. Поэтому обязательная передача как минимум 54599.8 кг: **68 минут 15 секунд** при 800 кг/мин, плюс 5 минут подключения и 10 минут обслуживания. Даже лучший наземный оборот — примерно **83 минуты 15 секунд**. Все исходные склады достаточны для этого первого пополнения; при повторных визитах поиск всё равно хранит реальные остатки.

## Границы поиска и уточнение

Реализован поиск последовательностей с точным сохранением складов и повторных визитов: максимум 8 перелётов, 5000 раскрытых состояний, горизонт 7 суток. В reference-прогоне раскрыт только корень, 101 ход отклонён, дальнейших состояний/победителей нет. Остановка здесь вызвана отсутствием первого ребра; предел глубины/узлов не достигнут. Это не поиск всех реальных аэродромов мира.

Солнечная проверка уточнена с eventTolerance 0.5 с / interval 900 с до 0.05 с / 300 с. Классификации всех направлений совпали; сдвиг старта около 0.0069 с, максимальное изменение найденного опасного UTC около 0.0195 с. Это численная сходимость общей модели, не уменьшение её астрономической ошибки: независимые пределы [SOLAR_MODEL.md](SOLAR_MODEL.md) сохраняются.

14 и 28 июня 2026, 21 июня 2027 проверены отдельно: те же категории и отсутствие первого хода. Эти точки не доказывают результат для каждого дня лета.

Чувствительность: длительности наземных фаз ±20%, расход ±10%, поток заправки ±20%, а также совместные оптимистический/пессимистический варианты. Во всех этих отдельных опытах первый ход также исключён; скорость, география, Солнце и исходный профиль файлов не менялись. Полная параметрическая/AFM-верификация не заявляется.

## Вариант для обсуждения, не изменение миссии

Отдельно диагностирован более ранний ночной старт при тех же данных/физике. За 2/3/6/9 часов до восхода оптимистические границы дают 1/9/28/32 потенциальных первых направления соответственно. За два часа — только Dulles; за шесть доступны, в частности, западное побережье и Honolulu. Для каждой границы нужен свой допустимый начальный запас; это не обещание всех ходов с одним F.

Эти опыты **не утверждены как новые условия и не подтверждают весь путь до Heathrow**. Наиболее прямой следующий эксперимент для решения владельца — исследовать более ранний ночной старт, сохранив реальную физику и остальные правила. Автозаправка, самолёт, дата или каталог не меняются скрытно. До решения владельца и нового подтверждения #22 не следует представлять как реализацию проходимой миссии.

Тесты покрывают геометрический восход и старт, интервал топлива/монотонность заправки, непрерывную опасность в пути/на земле, приоритет Солнца на терминальной границе, синтетический безопасный полярный переход, сохранение массы и конечных складов при повторных визитах, отказ без мутации, различие исчерпания и отсечения поиска, сверку всех артефактов, CLI/часовые пояса и коды отказа.
