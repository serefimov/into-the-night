## Журнал доказательств применения скилла

1. До реализации: обнаружены отсутствие видимой подписи, ограничение масштаба
   `Math.min(..., 1.5)` и привязка следования к текущему `playing` вместо намерения
   вернуться к самолёту. В планировании/на паузе навигация должна сохранять время.
2. До изменения игрового кода добавлен `scripts/test-center-browser.mjs`, подключён
   к существующему Chrome runner. Red-прогон на исходном UI завершился ошибками:
   пустая видимая подпись, масштаб `1.5 !== 3` / `1.5 !== 5`, отсутствие следования
   после центрирования на паузе и продолжения. Исправлены отдельно ошибки фикстуры:
   допустимый диапазон долготы, покрытие складов сокращённого каталога, CDP Enter.
3. Минимальное исправление: существующий SVG-контрол получил подпись, aria-label,
   подсказку и область ≥44×44; вынесен из колонки масштаба к верхнему краю карты.
   Его прямоугольник учитывается раскладкой меток. Центрирование вызывает текущую
   `view.state.position` без изменения масштаба и сохраняет намерение следовать.
4. Проверка выявила регрессию Tab-порядка при переносе кнопки; исправлена до
   коммита реализации. В runner обнаружена гонка удаления временного профиля Chrome
   (`ENOTEMPTY` после kill); добавлены ограниченные повторы удаления.
5. Стабилизированы наблюдения теста: сравнение полного состояния до/после одного
   click, ожидание фактического click, проверка primary pointer/touchstart,
   отдельные сценарии. Мгновенный touch drag из одного скачка давал down/up без
   click при следующем tap — локально и в первом CI. Жест заменён пятью движениями
   за 200 мс; на финальном runner прошли оба полных URL-прогона. Причина внутри
   распознавателя Chrome не измерялась, поэтому предположения о fling не считаются
   установленным фактом. Эксперименты с CSS, сбросом эмулятора и специальным флагом
   Chrome не помогли и не вошли в результат. Два исходных baseline Mutator со сбоем
   ввода были отвергнуты, а не засчитаны как убитые мутации.
6. Следующий CI при медленной навигации обнаружил чтение `body.dataset` до создания
   body. Ожидание исправлено: прежний документ помечается до навигации, затем
   проверяется новый документ и его `body?.dataset.ready`. Старый готовый DOM
   больше не может удовлетворить условие загрузки нового экземпляра приложения.
7. Не потребовалось менять архитектуру продукта или рефакторить физическое ядро.
   Большие исторические UI-функции не делились ради метрик. Коррекции тестового
   наблюдателя и очистки runner выделены в отдельный коммит.

## Проверяемые инварианты и критерии

| Критерий #40 | Проверка |
| --- | --- |
| Заметный единственный контрол | Видимый текст, title, aria-label, SVG path, ≥44×44, попадание в viewport |
| Фактическая позиция | Скрытый самолёт перед нажатием; совпадение камеры с `view.state.position` и проекции с центром карты в планировании, круизе и на паузе |
| Масштаб и читаемость | 0,75 / 1 / 1,5 / 3 / 5×; контроль пересечений самолёта/выбранного видимого аэропорта с кнопками; снимки desktop/mobile |
| Следование и исследование | Центрирование при playback; центрирование на паузе → продолжение; реальный mouse/touch drag освобождает камеру при продолжающемся UTC |
| Навигация без игрового действия | Полное сохранение, выбор, прогноз/принятый маршрут, tracks, playing и rate одинаковы до/после click в одном event dispatch |
| Доступность | Mouse, touch с наблюдаемым pointerType, Tab, Enter, Space, focus-visible; 1280×900, 390×844 и 320×844 |
| Географические границы | Реальный CYEG → UHMA с долготами обоих знаков и синтетический северный зимний вид 89,5° |

Написанные до исправления восемь групп проверок (девять на mobile с узким экраном)
исполняются в браузере, а не ищут строки в HTML/JS. После реализации уточнялись
синхронизация ввода и охват нового положения кнопки; сложная группа
разделена на две независимые проверки, итог — девять desktop / десять mobile. Полярная фикстура проверяет
только навигацию и не является заявлением о проходимом игровом маршруте.
При большом масштабе выбранный дальний аэродром может быть вне viewport: сохранение
масштаба не означает одновременную видимость всей дуги. Видимые метки учитывают контрол.

CRAP **N/A**: `--no-coverage`; корректный отчёт покрытия ветвей DOM-обработчиков
не получен. Не подставлялось покрытие Node/CLI и не использовался фиктивный ноль.

`.ts` без изменения содержимого. Это ограничение метода, не доказательство

## Воспроизведение

```sh

npm run check
npm run build:web
CENTER_ONLY=1 npm run test:browser
npm run test:browser
SPIKE_TEST_BASE=/into-the-night/release/0.1.0/ npm run test:browser
# Для диагностики отдельных сценариев: CENTER_TRACE=1
```

Здесь настроенное зеркало npm возвращало HTTP 500 для astronomy-engine.
Те же зафиксированные версии установлены из публичного npm через `--no-save
--package-lock=false`; package.json и package-lock.json не изменялись.
Chrome/localhost требовали выхода из sandbox. Проверки — эмуляция Chrome,
не физический телефон и не Safari/Firefox; полярный вид синтетический.
Touch проверен настоящими CDP pointer/touch-событиями, с траекторией из пяти
движений за 200 мс и отдельным tap. Физический телефон отдельно не проверялся.
Токены и денежная стоимость этого запуска недоступны; они не оценивались по длине
текста или проценту общего лимита аккаунта.
