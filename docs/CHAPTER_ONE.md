# Глава 1: Академгородок (#64)

Кампания использует отдельный [сценарий v1](../data/scenarios/chapter-one-v1.json):
**Пулково, 10 августа 2026 19:00 UTC, 65000 кг на борту**; конечные склады прежние,
по 64000 кг. Профиль B788-reference-v1, Солнце, скорость, массы и заправка не менялись.
Исторические [аэропортовый сценарий](../data/scenarios/academic-westward-v2.json) и
[отчёт](ACADEMIC_WESTWARD.md) сохранены. Главная страница запускает кампанию;
`web/flight/index.html?scenario=airport-spike` открывает прежний аэропортовый этап.
CLI по умолчанию сохраняет прежний сценарий; кампанию выбирают явно.

## Точка, дорога и источники

Точка получения — **НГУ, ул. Пирогова, 1, Академгородок**,
54.843157° N, 83.094035° E: дорожный подход к университетскому комплексу.
[НГУ](https://www.nsu.ru/) — реальный университет. Локальный архив, час доступа
и знание о защите от Солнца — вымысел; существование такого архива не утверждается.
Официальный сайт при проверке из рабочей среды возвращал 403/пустой ответ;
геометрия подхода взята из указанного ниже открытого маршрутизатора, а не из
предположения о доступности внутренних помещений.

Дорога проходит через Толмачёвское и Советское шоссе, Приморскую и Русскую
улицы, Бердское шоссе и Университетский проспект (имена из OSRM steps).
Две отдельные трассы OSRM driving/OpenStreetMap получены 28.10.2026 и сохранены
в [outbound.json](../data/campaign/chapter-one/outbound.json) и
[return.json](../data/campaign/chapter-one/return.json). В каждом файле есть точный
URL запроса, дата, исходные/привязанные точки, полная GeoJSON-трасса и лицензия
**© OpenStreetMap contributors, ODbL 1.0**. Прямой запрос можно повторить, но
актуальная сеть OSRM изменяема: воспроизведение игры использует сохранённые файлы,
их SHA-256 входит в [машинный отчёт](chapter-one/report.json).

Туда 48.432 км, обратно 49.959 км: это две дорожные трассы, обратная не заменена
разворотом дороги с односторонними участками. Запрос у терминала —
82.6507° E, 55.0126° N; OSRM привязал его к дороге в 548 м от запроса.
Центр аэродрома из pinned OurAirports (55.019756, 82.618675) соединён с дорожной
точкой короткой дугой в начале/конце; это упрощённый трансфер по аэропортовой
территории, а не утверждение о разрешённой автомобильной дороге через перрон.
Общий трансфер входит в те же 90 минут, не телепортирует группу и проверяется
на Солнце. Привязанные точки у НГУ одинаковы для обоих направлений.

OSRM оценивает движение примерно в 62.7/61.7 минуты; это расчёт маршрутизатора,
не подтверждённое реальное ночное время. Игра закладывает **90 минут в каждую
сторону + 60 минут на доступ/копирование данных = 4 часа**. Разница с расчётным
движением оставляет время на аэропортовый трансфер, посадку в машину и подход к
архиву. Скорость по каждому короткому сегменту пропорциональна длине; стоянки
и трафик не моделируются отдельно. Машина, корпус НГУ и оставленный борт
не получают дневной неуязвимости. Автотопливо/провизия не вводятся в #64:
топливо B788 и склады во время вылазки не расходуются и не пополняются; #33
добавит провизию и массу с повторной проверкой главы.

## Бюджеты и выбор условий

Сравниваются игровые кандидаты: 3 ч = 60/60/60 минут; 4 ч = 90/60/90;
5 ч = 120/60/120. Это чувствительность бюджета, не три утверждения о реальной дороге.

| Условия | Бюджет | Вся экспедиция | Безопасных немедленных следующих рейсов |
| --- | --- | --- | ---: |
| Старый старт 01.08 20:00, 30 т | 3 ч | безопасна; после возврата лишь 7 мин до восхода у борта | 0 |
| Те же | 4 ч | Солнце на обратной дороге | 0 |
| Те же | 5 ч | Солнце на обратной дороге | 0 |
| Новый старт 10.08 19:00, 65 т | 3 ч | безопасна | 138 |
| Те же | **4 ч** | **безопасна, 72 мин до восхода у борта** | **8** |
| Те же | 5 ч | безопасна, 12 мин до восхода у борта | 0 |

Три часа не выбраны ради старого зелёного финиша: они даже чуть короче исходной
оценки движения с часом работы и не оставляют места на трансферы. Четыре часа
обоснованы независимо от маршрута самолёта. Пять часов показывают, почему
одной безопасной экспедиции всё равно недостаточно для продолжения.

Сначала проверены 25 опубликованных западных цепочек при старых условиях:
ни одна не даёт четырёхчасовую вылазку. Затем сравнивались старты
01/10/15/20 августа, 19:00–20:00 UTC через 15 минут, с 30/65 т на борту, по
основной цепочке. Полные параметры и результаты — `startGrid` отчёта. Это
ограниченный поиск, не доказательство невозможности других путей/дат/ожиданий.
Выбран 10 августа 19:00: старт в ночи, прямой ULLI → UNNT пересекает Солнце,
на Шпицбергене непрерывно подтверждён полярный день 10–11 августа. Дополнительное
начальное топливо законно по всем массам первого рейса; оно не создаётся при
загрузке или прибытии. Начальные 65 т и более ранний вечерний старт дают меньше
исходных заправок и более ранний финиш. Север и восток не запрещены кодом.

## Сквозной свидетель

**ULLI → BIKF → CYEG → UHMA → UNNT**, те же 16447.274 км и −307.644°
развёрнутой долготы. Прибытие 11.08 17:42:21 UTC, обслуживание до 17:52:21,
5000 кг на борту. Прибытие оставляет статус `running`, без знания/победы.

| Действие | UTC 11 августа |
| --- | --- |
| Дорога в НГУ | 17:52:21 → 19:22:21 |
| Получение данных | 19:22:21 → 20:22:21 |
| Возвращение | 20:22:21 → 21:52:21 |
| Заправка и следующий рейс UNNT → UACC | заправка 21:52:21 → 22:06:53; посадка 23:36:37, обслуживание до 23:46:37 |

Знание №1 выдано единожды в 20:22:21, глава завершена только при возвращении
в 21:52:21. Затем открыт следующий ориентир «Цукуба за наводкой»; главы #31/#65
пока не реализованы, победы кампании нет. Восход у НГУ около 23:03:05, у борта
23:04:22 UTC; эти точки проверяются раздельно. 72 минуты — запас **у самолёта
после возвращения**, а не замена проверки всей дороги на аэропортовый восход.
Все дорожные сегменты, час на месте и конечный UTC проверены общим
`checkRoutePhaseSafety`, отдельно проверена вся стоянка самолёта.

Продолжение использует реальные остатки: перед UNNT → UACC заправляется
7632.394 кг из склада UNNT, а не из нового состояния. В UACC в конце 23:46:37
на борту 5000 кг; остатки изменённых складов CYEG 42907.202, UHMA 30185.515,
UNNT 56367.606 кг, остальные 64000. Это безопасный следующий переход, не
подтверждение полной главы Японии. Точные дробные UTC и массы — в отчёте.

## Ядро, карточка и сохранение

`MissionSession.forecastExpedition/startExpedition`, `stateAt/stopAt/resume`
используют один план из `mission-ground.ts`: `ground_outbound`,
`ground_acquisition`, `ground_return`. Во время вылазки `position` — фактическая
группа, `aircraft.position/airportId` — оставленный UNNT, `airportId=null`.
Полёт/ожидание и повторная вылазка заблокированы. Путь уже сертифицирован целиком;
опасная/неопределённая вылазка отклоняется без мутации, как опасный рейс.
Длительность не зависит от FPS. Пауза удерживает курсор, reload стартует на паузе.

Модель `campaign-ground-v1` / `flight-ground-1`, состояние/события 4, envelope 6.
Сохранение содержит определение дорог, журнал принятых действий, курсор,
потреблённые события и проверяемый повторным расчётом снимок. Знание/завершение
выводятся из фактического курсора; подделка и дубликат операции отклоняются.
Исторические envelope 3/4/5 сохраняют прежние режим и семантику. В браузере ключи
`into-the-night-campaign-v1` и `into-the-night-flight-v3` разделены; несовместимое
сохранение не преобразуется в кампанию молча.

Карточка ещё до вылета в UNNT показывает три длительности, UTC данных и
возвращения, достаточность всей ночи, расчётный запас и конкретный этап встречи
Солнца при позднем прибытии. Она не обещает безопасность следующего рейса:
его карточка рассчитывается из фактического состояния после возвращения.
На глобусе оставленный самолёт и группа имеют отдельные значки; кнопка
центрирования во время вылазки следует за группой.

## Воспроизведение и проверки

```sh
npm ci
npm run check
npm run research:chapter-one
npm run validate:chapter-one
npm run mission:cycle -- --definition data/scenarios/chapter-one-v1.json --path examples/chapter-one/witness.json
# Экспорт из браузера можно продолжить CLI без смены сценария:
npm run mission:cycle -- --load ground.json --resume
npm run build:web
npm run test:browser
```

`research:chapter-one -- --write` явно обновляет эталон; обычная проверка его
не перезаписывает. Машинный свидетель проверяет обычный и уточнённый решатель,
полный западный путь, отдельные бюджеты, единственность знания, возврат и UACC.
Тесты ядра включают рассвет на обратной дороге, конечный солнечный UTC,
неопределённость, неизменность отказа, все три фазы pause/save/load и старые saves.
Браузерная проверка 1280 px и touch 390/320 px проходит вылазку/перезагрузку,
экспортирует промежуточный журнал в CLI, проверяет карточку позднего прибытия и
безопасный следующий рейс. Скриншоты — `.build/previews/chapter-one-*.png`.
