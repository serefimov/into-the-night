# Into the Night — инструкции для Codex

## Цель проекта
Географическая миссия на карте/глобусе: JFK → Heathrow летом, старт за час до геометрического восхода. Игрок выбирает следующий аэродром и подтверждает кнопкой «Полёт» в карточке. Реальная физика, один реальный дальнемагистральный самолёт, максимальная автозаправка, без еды и пока без ручного ожидания. Точные параметры и достижимость ещё требуют #20–#21. Принятые решения — GAME_DESIGN.md и docs/CONCEPT_REVIEW.md.
Сначала прочитать GAME_DESIGN.md, SIMULATION.md и SCENARIOS.md. Правила пользователя имеют приоритет. Числа, помеченные как стартовые параметры, разрешено настраивать с объяснением результата; принятые механики не менять молча.

## GitHub и Git — обязательные правила
- Одна задача GitHub — одна ветка. Работать в ветке соответствующего issue, не объединять разные задачи в одну ветку.
- Имя ветки начинается с номера issue: `1-init`, `12-solar-model`.
- Все сообщения коммитов начинаются с номера задачи: `#1 добавил лицензию`.
- После номера описывать сделанное в прошедшем времени, со строчной буквы. Не использовать инфинитив.
- Коммиты атомарные. Несвязанные изменения не объединять.
- Примеры: `#2 реализовал расчёт положения Солнца`, `#3 исправил расход еды при погрузке`, `#5 добавил проверки полярной ночи`.
- Неправильно: `добавил модель Солнца`, `#2 Добавить модель Солнца`, `#2 Добавил модель Солнца`, `feat: solar model`.
- Номер брать из реального issue. Номера в примерах не означают, что такие задачи уже созданы.
- Если номер или репозиторий недоступны, подготовить изменения и описание задачи; не придумывать номер для коммита и не делать коммит без обязательного префикса.
- Перед работой проверить status и текущую ветку. Чужие незакоммиченные изменения сохранять. Не сбрасывать и не переписывать историю без явной необходимости и разрешения пользователя.
- Каждая задача содержит цель, границы и проверяемые критерии. В PR описать итоговое поведение и выполненные проверки. PR вливает только владелец проекта. Codex готовит PR с результатом и проверками, но не выполняет merge.

2. #20: источники и профиль реального самолёта, мировой каталог аэропортов и отдельные конечные игровые запасы.

5. #23: глобус, карточка и кнопка «Полёт»; минимум управления, mouse/touch.
6. #24: второй playable spike, сохранение/итог, Pages и рецензия владельца.

Реальная физика имеет приоритет над проходимостью: нельзя менять скорость, Солнце или расстояния ради миссии. Ненайденный путь не доказывает невозможность. Прежние модели/документы в docs/history и результаты OSL/TOS/LYR сохраняются как исторические; 30–365 суток не являются целями новой миссии.

## Архитектура и качество
Предпочтение для нового проекта: TypeScript, общий вычислительный модуль для браузера и CLI. Это техническая рекомендация, а не ранее выбранный пользователем стек. Выбор движка глобуса обосновать после проверки мобильного управления, терминатора, маршрутов через 180° и полюса. Не создавать вторую независимую модель Солнца в визуализации.

Симуляция не зависит от FPS, камеры, DOM, сетевого доступа и скорости анимации. Генерация мира воспроизводится по seed и версии конфигурации. Статические данные и конечные игровые склады разделены. В новой миссии топливо аэропортов публично. В историческом режиме его прежняя политика скрытых сведений сохраняется; не менять её молча.

Тестировать содержательные инварианты: непрерывную безопасность маршрута, первый момент поражения, баланс топлива и автозаправки, геометрический восход, сохранение/продолжение, неизменность заблокированного вылета. Новую проверку добавлять при изменении существенной логики, а не ради покрытия строк.

## Готовность задачи
Реализованы критерии issue; необходимые проверки прошли; команда воспроизведения указана; ограничения описаны; затронутые документы актуальны. Не выдавать демонстрационные данные и непроверенные маршруты за подтверждённые.

## Передача результата пользователю
Кратко: что изменилось, чем проверено, что остаётся неопределённым. Не считать принятие этих документов разрешением создать внешние issues, отправить PR или опубликовать игру без соответствующей задачи.
